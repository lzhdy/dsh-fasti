## 1. 系统背景（给外部读者）

这是一个为长期运行的 AI 伴侣构建的记忆系统，存储分三层，外加一个很小的"工作记忆窗口"：

| 层 | 存什么 | 体量/特性 | 可变性 |
|---|---|---|---|
| **记录本（真源）** | 每一轮原文 + 结构化"经历"条目 | 全量、最大、append-only | **永不修改、永不删除**，是唯一权威 |
| **记事本（事件投影）** | 把连续流水自动切成的"事件"，每个事件带一段第三人称摘要、关键点、锚点指针、话题线 | 中 | 可从真源完全重建的投影 |
| **记忆本（长期记忆投影）** | 复盘时，她判定"值得长期记住"的事件 | 最小 | 可重建的投影；**本稿讨论的对象** |
| **工作记忆窗口** | 聊天时她眼前常驻的一小段记忆，当前约束约 **700 字 / 5 件事** | 极小、实时 | 由检索动态填充 |

已有工程纪律：

- 正文只存一份，别处只放**指针**，需要时沿指针回原文取（系统已有指针解析原语）。
- 一切投影（记事本、记忆本、索引、未来的实体/情绪表）都可从真源重建，做错了能推倒重来，真源不受影响。
- 事件摘要时已产出两类压缩物：`key_points`（几条要点短句）、`anchors`（指向具体经历的 id 指针）。
- 当前全文检索只有基于词面的 trigram/FTS，**没有向量/embedding 层**。

## 2. 现状方案与新提议

- **现状设计**：复盘时把"值得记"的事件**摘要**放进记忆本。等价于记事本的一个筛选子集——
  只是撕掉了她认为不值得记的东西，单条体积没有进一步缩小，且与记事本存在摘要副本冗余。
- **新提议（待评审）**：记忆本不再存摘要，只存**关键词/线索 + 事件指针（+ 极短消歧信息）**。
  回忆时走三级回跳：
  1. 当前话题触发记忆本里的**关键词线索**；
  2. 沿指针到**记事本**读事件摘要，想起"大致发生了什么"；
  3. 需要细节时再沿指针到**记录本**读原文，还原"当时的全部记忆"。

## 3. 提议者本人已识别的优缺点

**预期收益**

1. 记忆本体量大幅缩小。
2. 同样 700 字的工作记忆窗口能容纳更多件事（线索比摘要短得多）。

**已担心的缺点**

1. 记忆失真更多。
2. 多件事可能共用相同关键词，导致"记叉"（错误关联）。
3. 回忆要连走三个点，可能更慢。
4. 预感还有没想到的其他缺点——这正是本稿外发评审的原因。

## 4. 与现有架构的契合点（内部分析，供外部判断是否成立）

- 系统早已贯彻"正文一份 + 指针引用"，新提议是同一原则向记忆层的延伸，而非范式突变。
- 记忆本是可重建投影，改它不碰不可变真源，试错可逆。
- 指针解析、事件锚点、关键词式 FTS 都是现成零件，工程增量主要在"复盘产物形态"和"检索排序"，
  不需要新存储引擎。

## 5. 业界与学界的同构方案（2025–2026）

新提议并非孤立构想，以下工作在结构上高度相似，**但它们也各自暴露了代价**：

- **SAM（State-Adaptive Memory, arXiv 2605.24468）**：把交互历史压缩成紧凑的"记忆线索
  （compact cues）"作为轻量句柄，原始轨迹页完整保留，按当前意图驱动召回与重建；明确强调线索
  **不是历史的替代品而是把手（handle）**，报告在多个长程任务上优于基线。
- **H-MEM（arXiv 2507.22925）**：按语义抽象程度分层，每条记忆带"位置索引"指向下一层相关
  子记忆，检索时索引路由逐层下钻，避免全量相似度计算。
- **MemTier（arXiv 2605.03675）**：两阶段检索——先在语义层用 BM25 粗取少量会话 id，再只加载
  这些会话的条目精排，把检索池从全量缩到聚焦子集，防止上下文溢出。
- **Letta / MemGPT 的热温冷三层（core/recall/archival）**：用操作系统分页隐喻管理记忆。
  其被公开承认的弱点是：让 LLM 通过函数调用自主决定分页/换入换出，会在**每次交互**上叠加
  延迟与 token 成本。→ 对本方案的警示：三级下钻的"是否下钻"决策不应每轮都交给大模型。
- **Mem0**：单遍 ADD-only 抽取（只增不覆盖）、用软重排而非硬删除处理过时、按近因做 0.3×–1.5×
  衰减、混合检索 + 实体链接，并把单次检索取回的上下文控制在约 7k token 内。
- **lycheemem**：工作记忆达阈值时异步预压缩，产物是"摘要锚点 + 最近原文"双轨，不阻塞当前请求。
- **zenbrain**：仅把**情绪权重高于阈值**的情景巩固为长期语义事实——支持"按重要度/情绪分级保留"
  而非一律只存词。

## 6. 认知科学揭示的风险（比直觉更具体）

1. **线索依赖遗忘（cue-dependent forgetting / 编码特异性）**：提取能否成功，取决于检索线索与
   当初记忆痕迹是否匹配；线索不对，记忆明明还在也提取不出。→ 纯关键词会有"在嘴边却想不起来"
   的系统性失败，必须保留不依赖线索的兜底通道（全文检索、时间轴浏览）。
2. **基于大意的错误再认（gist-based false recognition，DRM 范式）**：人会因"大意相似"认错事件；
   研究指出这类错误**不是细节丢失造成，而是检索阶段大意匹配压过了细节区分**。→ 硬设计含义：
   关键词只能用于**粗召回**，在对外认定"就是那件事"之前，必须下钻到摘要/原文做区分确认，
   不能只凭关键词下结论。
3. **部分线索抑制（part-list cuing / 检索竞争）**：只呈现一部分线索反而会抑制其他相关记忆的
   提取，线索彼此竞争。→ 记忆本不是词越多越好，需要线索数量预算与权重排序，否则高频词刷屏、
   挤占工作记忆窗口。
4. **错误信息效应（misinformation effect）**：事后的错误信息会被误认为原事件的一部分。本系统
   真源 append-only 不可变，投影/线索即便记错也能回真源核验——这是相对人脑与许多框架的结构性
   优势，应在设计中明确"争议时以真源为准"的回退路径。

## 7. 工程检索手段与当前缺口

- 纯词面检索（BM25/FTS）在"换了个说法/同义表达"时会漏；生产实践普遍收敛到**混合检索**：
  关键词与语义向量并行召回 → RRF（倒数排名融合）合并 → 必要时交叉编码器重排，可将检索失败率
  降低一半以上；更省成本的做法是级联路由：先用便宜的关键词查，置信度不足再上向量。
- **本系统缺口**：目前只有 trigram 词面 FTS，没有 embedding/向量层。若记忆本只存关键词，
  召回会偏脆；向量层属投影增强、不碰真源，但需要决定引入时机、向量存放位置与融合方式。

> **文献边界声明（v0.2 勘误）**：第 5、7 节引用均基于论文摘要级信息，只作为"结构同构旁证"，
> 不等于对本方案纯关键词形态的实验背书。需特别收紧三点：① SAM 的 cue 实际是"轻量文本摘要
> 兼句柄"（含已确认/已排除/未解决等状态），并未验证"2–5 个关键词 + 指针"这一具体形态；
> ② MemTier 的收益很大部分来自结构化"实体—关系—值"语义事实而非关键词压缩，更支持
> "语义事实 + 混合召回"；③ "混合重排使失败率减半"出自特定数据集（LoCoMo 等）、固定模型与
> 检索预算下的实验，不可外推为普遍生产结论。正式立项前应精读原文复核（见附录 A 第 7 条）。

## 8. 初步护栏与目标（v0.2 修订，仍候选、欢迎挑战）

**优化目标（v0.2 换轴，v0.6 翻转方向）**：不是"记忆本占盘更小"（本地磁盘从不是瓶颈）。

- v0.2–v0.5 表述为"在质量前提下最小化每次正确回忆的 token 与延迟"（质量做约束、成本做
  目标）。**v0.6 修正为反向**：对以"存在连续/被理解"为核心的伴侣系统，应是
  **在 token/延迟预算约束下最大化记忆质量**（质量是目标，成本是不可突破的预算上限，
  工作窗口 700 字即天然硬预算）。
- 命门：三个质量红线（证据召回率下限、错误事件认定率上限、叙事/自我一致性下限）**必须
  给出具体初始阈值**，否则"最小化成本"总能靠偷偷调低质量门槛作弊，评测驱动也会因无判定
  基准而悬空。初始值允许是经验占位值，但须显式写出并在 harness 跑通后用数据校准
  （D2 已定：先观测后定硬阈值，见附录 E.6）。
- 同时避免靠极端压缩拿"容量收益"，却把成本转嫁成更多下钻、更多误认和更差回答。

1. **记忆条目用"类型化轻卡"而非裸词**：少量锚点词 + 稳定事件指针 + 一句 20–40 字的
   `gist`（只回答"谁、发生了什么、为何值得记"，不保留经过，故不是退回完整摘要）+
   时间/通道/关键实体。第一版取**最小字段集**，有效期、取代关系、认识论状态等随 facts/
   关系能力分阶段引入，不一次铺满（字段映射与约束见附录 A）。
2. **下钻按证据等级分级，不做"一律下钻"硬规则**：判断候选相关性，线索即可；宽泛提及往事，
   至少读事件摘要；引述原话/日期数字/承诺/敏感属性/强情绪，或遇用户质疑、候选冲突、
   同实体多事件、否定性结论，必须读原文并比较候选。**检索分数只决定是否扩大召回，
   不等于事实置信度。**
3. 三级回跳是三个**逻辑层级，不是三次模型往返**：检索服务可一次批量返回"前 N 张卡 +
   头名事件摘要"，原文再按需批量取回，避免 Letta 式逐轮 LLM 分页开销。
4. 召回走"词 + 未来向量"混合，并保留 FTS/时间轴兜底，防线索依赖遗忘；**向量层延后**，
   等实测证明"释义不同导致漏召"是主要瓶颈再引入（数据驱动，不预先堆技术）。
5. 线索设**数量预算 + 权重/衰减**，衰减只影响排序、**不抹除事实状态**；过时事实靠显式
   `supersedes` 取代关系处理。工作窗口先试"3 张卡 + 1 份事件摘要"按 token 动态装填，
   不预设始终塞满固定条数。
6. **单独维护一条低频"自我叙事线"**（按人生阶段的少量章节摘要 + 事件指针），服务身份连续
   与因果，不每轮进窗口、不靠访问权重维持；与服务日常检索的记忆卡分轨（回应 Q9）。
7. 重要度/情绪强度只作为**记忆卡投影的排序权重**，依据 A 块冻结纪律，不进真源经历字段
   （契约明确不设 importance/salience/priority）。

**v0.3 增补护栏（源自第 2 轮外审，论证见附录 B）**

8. **"可重建"要从承诺落成机制**：每张卡写入时附一条 append-only 决策记录（输入事件 id 集、
   产出卡、模型/prompt 版本、理由），使重建=重放决策日志而非重跑漂移的推理；承载位用规划中
   尚未实现的 P8 `judgment_ledger`，不另造。事件身份须与切分算法版本解耦（现状风险见附录 B）。
9. **卡片双形态**：存储态（gist + 全字段，驻记忆本）与窗口态（2–3 锚词 + 类型标，进工作
   窗口）分离；窗口压缩是本地确定性渲染、零模型往返。窗口用**槽位制**（近因/身份/相关/义务
   各配 token 预算）而非纯相关度排序，避免饿死近因与身份记忆。
10. **生成侧纪律（不只在检索时下钻）**：仅指针、无 gist 的卡必须显式标注"勿自行展开"，
    防止模型凭裸词编造细节渗入语气；任何带具体时间/地点/承诺的输出断言必须挂原文出处
    （provenance 校验），挂不出则降级为不确定。
11. **义务/缺席型记忆（"别再提 X""记住 Y"）绕开窗口竞争**：常驻或实体触发，不参与相关度
    排序——其触发最依赖巧合、失败代价最高。线索 schema 加可选 context tags（地点/时段/
    心境/媒介物）应对情境式回忆；卡元数据带灵敏度位，敏感 gist 的窗口态退化为类型标 + 指针。
12. **评测先于改造**：第一步先搭"真实回忆情节"评测 harness（详见附录 B 盲区 2），让
    Q3/Q6/Q7/Q10 在动架构前就有数据尺子；v1 检索保持平凡（BM25/IDF + 近因先验），
    实体倒排索引优先于向量层。

## 9. 请重点挑战的开放问题

1. 消歧卡要带多少信息才够防"记叉"？加到什么程度就退化回了"小摘要"、失去缩减意义？
2. "何时必须下钻、何时可凭线索直接作答"的判据怎么定？能否给出可实现的置信度规则？
3. 线索由复盘阶段的 LLM 一次性生成，如何**评测选词质量**？有没有不依赖人工的自动评测办法？
4. 关键词会老化、多义、随语言演化；线索重建的周期与触发策略应如何设计（投影可重建，但是否
   全量重算、增量更新）？
5. 工作记忆窗口到底放多少条线索合适？权重与衰减函数有没有可借鉴的成型方案？
6. 向量层应在什么规模/痛点下引入？embedding 模型升级导致向量失效时如何迁移？
7. 情绪、氛围、微妙语境这类难以词化的记忆，分级保留的客观标准是什么？
8. 三级回跳的延迟与 token 预算如何分配？在工作记忆窗口里如何平衡"线索数量"和"下钻次数"？
9. **摘要不只压缩信息，还提供叙事连贯性与因果脉络**；碎成词表后，她通读记忆本时会不会失去
   "故事感/自我连续性"？这个损失对一个以"存在连续"为核心目标的系统是否可接受？是否需要保留
   一条低频的"叙事线"作为补充？
10. 如何做 A/B 评测，用数据证明关键词版相对摘要版在召回率、准确率、延迟、token 上的真实差异，
    而不是凭直觉选型？

### B.1 结构性盲区（已做代码核实，非照单转述）

**盲区 1："可重建投影"目前是承诺、不是机制。** "值得记住"是判断而非可推导函数；
LLM 复盘产物的"重建"要么确定性重放、要么重跑推理（随模型版本漂移），后者是最弱的一种。
处置：**采纳**，并核实两点事实——

- 决策记录的承载位已在规划中：`src/projection/schema.ts` 把 `judgment_ledger` 列为
  完整投影集 P8（阶段 0–2 未实现）。未来每张卡的"输入事件 id 集 / 产出卡 / 模型与
  prompt 版本 / 理由"写入该台账即可，**不另造机制**。事件层现有的
  `summary_model / summary_prompt_version / summary_source / created_by` 留痕已是同纪律雏形。
- **事件 UID 风险经核实属实**：`src/event/segmenter.ts:801` 与 `src/event/correction.ts:291/361`
  中事件 id 均为随机 `defaultUlid.next()`；split 一对多拆出的新事件取新 id。这意味着切分
  算法升级确实可能使记忆本指针失配。"事件身份与切分算法版本解耦、UID 一次分配不再重生"
  列为**正式待办**，不是纸面提醒。
  > **v0.5 方向修订（见附录 D.3）**：不再追求"让事件 UID 不重生"——切分升级时事件边界本身
  > 会变，强保 id 反而语义错位。改为记忆卡权威指针锚定**不可变真源锚点（经历/轮次 id）**，
  > 事件 UID 降级为可重建的解析缓存。现有事件 `anchors` 本就指向真源经历 id，数据基础具备。

**盲区 2：真源里躺着现成的评测金标——真实回忆情节。** 后续轮次自发重提某早期事件的
（查询轮, 目标事件）对，是零标注、天然时间切分防泄漏的正样本，可同时回答 Q3/Q6/Q7/Q10。
处置：**采纳**，并加两条校准——

- "用户主动重提 = revealed importance"由**行为推导**、只作投影排序权重、不落真源，与
  附录 A.1 的冻结纪律天然契合。但它是**单向正信号**：未被重提不能反推"不值得记"而淘汰
  （有些记忆未来才用、或私密到不会被提起），只用于正向排序与选材学习，不做负向删除依据。
- 检测"重提"本身仍需 LLM，存在"用 LLM 评测 LLM"的循环风险，须离线计算 + 抽样人工核验精度。
- 向量引入据此获得可操作阈值：真实情节中 FTS top-k 的语义漏召率超过 X% 才上向量；
  迁移时只对真源派生物（摘要/要点/原文块）批量重嵌入，RRF 对模型更换稳健，重建即可迁移。

### B.2 工程优先级（采纳）

记忆卡规模预计几百到低千级，此规模下混合检索/重排相对 BM25+IDF 的排序差距很小。
**v1 用最平凡检索（BM25/IDF + 近因先验）**，把工程投到评测 harness、窗口装配、下钻判据；
**实体倒排索引排在向量层之前**（更便宜、确定性、可重建，并直接支持跨事件聚合与撞词消歧），
承载位为 edge 表与未来 P3 实体表。

### B.4 新增失败模式（采纳，落护栏 11）

1. **裸卡诱发编造**：模型会给裸词愉快补细节，即便不"认定事件"也会渗进语气 → 无 gist 卡
   显式标"仅指针、勿展开"，下钻判定前移到生成时。
2. **义务/缺席型记忆最弱**（"别再提 X""记住 Y"）：靠线索巧合触发、失败代价最高 → 常驻/
   实体触发，不参与窗口相关度排序。
3. **语境线索化丢失**：未来查询常是情境式（"那个下雨天""那首歌"），而复盘偏爱大意词 →
   加可选 context tags（地点/时段/心境/媒介物），正合编码特异性原理。
4. **敏感标记缺失**：卡元数据设灵敏度位，敏感 gist 的窗口态退化为类型标 + 指针，对接既有
   垃圾桶/转痕隐私设计，不假设卡永久留存。

### B.5 建议落地顺序（采纳为路线候选，非实施承诺）

1. 先搭"真实回忆情节"评测 harness——不依赖任何新架构，建成即给 Q3/Q6/Q7/Q10 数据尺子；
2. v1：类型化双形态卡 + BM25/IDF + 槽位窗口 + 意图分级下钻，实体倒排索引第二优先；
3. 落 P8 决策日志与事件 UID 稳定化，让"可重建"由承诺变机制；
4. 影子评测测分歧率，再决定是否全量 A/B 与向量层时机。

### B.6 v0.3 阶段性共识

在 v0.2 基础上新增两条主线：**评测先行（先有尺子再动结构）**与**可重建机制化（决策日志 +
事件身份稳定）**；工程上 v1 刻意保守（平凡检索、向量最后）。三轮共识始终不变的底线：
真源 append-only 与 A 块冻结面不动，记忆本/叙事线/台账/实体/权重全部是可重建投影，
重要度不写真源、客观档案不被第一人称代笔污染。继续征集外部评审后定稿。

## 附录 C：第 3 轮外部评审意见与处置

来源：QoDuck（2026-11-10，用户转发；对方仅有本文档、无项目代码，意见基于文档本身）。
对方认可 v0.3 方向，提两处重心校正、三个缺失闭环、一个结构性矛盾。下文含我方代码核实
与对前两轮意见的冲突裁决。

### C.1 重心校正：本项目的真名是"窗口装配 + 证据纪律"（采纳）

几百到低千张卡规模下，裸词/摘要的存储形态差异对目标函数影响很小；决定质量的是
①什么进 700 字窗口、②生成侧是否诚实使用。存储形态之争正式降级。

- 三级回跳应理解为**证据层级**（线索/摘要/原文对应不同可信粒度），**不是检索路由层级**。
- v1 对全量卡做**平坦 BM25**，并明确**现阶段不引入 H-MEM 式逐层索引路由**——该优化只在
  大规模成立，此规模徒增故障点；第 5 节引 H-MEM 仅为结构同构旁证，不代表照搬其路由。
  若未来卡量/延迟实测越界再议，不永久封死。

### C.2 线索修复闭环 + 全量重生成裁决（采纳，并修正附录 B）

编码特异性决定"最好的线索是未来查询的措辞，而复盘时不可知"，故一次性选词必有系统性
漏召；与其只评测选词，不如运行时修复选词：

- **漏召埋点**：当线索路径未命中、而兜底通道（FTS/时间轴/实体索引）命中时，记录
  （查询, 目标事件）为漏召样本；将真实查询措辞**增量回填**进该卡线索（只增不覆盖、
  留痕进台账）。纯埋点、零架构改动，同时持续喂养 Q3 漏召率、Q4 老化触发、Q6 向量判据。
- **冲突裁决（与附录 B.3 的"季度全量"）**：全量重跑即重跑漂移推理，正是 B.1 警告的最弱
  路径。故**取消季度全量为默认**，日常只做增量回填；全量重建仅限模型/prompt 版本变更，
  且先影子 diff 再切换。B.3 对应行已加修订标注。

### C.3 义务/承诺独立成"约束表"，不放记忆卡（采纳为 v1 候选）

护栏 11 让义务记忆常驻，但 P3 实体触发未实现前常驻是唯一手段，而常驻吃掉最稀缺的窗口，
存在内在张力。本体论上"别再提 X/记住 Y"是**待执行的当前约束**，不是**待回忆的往事**，
生命周期与注入方式都不同。方案：独立微型**常备约束表**（几十条上限、每轮注入、
不参与检索排序、显式 supersedes/失效），与记忆本分表。约束仍须：①可从真源重建并保留
指向源头对话/反思的指针；②失效/取代走双时间机制；③不依赖 P3 即可在 v1 先做常驻注入。

### C.4 评测 harness 的三个补强（全部采纳）

1. **金标有幸存者偏差**：用户重提常由她自己的话触发，而她的话来自当前系统检索，故真实
   情节测的是"当前检索分布"而非真实需求分布。须分层统计（用户主动冷回忆 vs 伴侣引发），
   并保留一批从未 surfaced 的事件做 holdout。此点把 B.1 的"循环验证风险"落到了可操作方法。
2. **误认率主动构造、不等自然错误**：自动生成 DRM 式诱饵——取 gist 最相似事件对做
   "同话题不同事件"探针，零标注直击记叉（呼应第 6 节 DRM）。
3. **Q9 此前不可测**：补第二轴"自我一致性探针"，跨时间追问她的自我描述/过往表态是否
   一致，否则身份连续这一核心目标始终没有尺子；也用来检验第一人称叙事线是否真的增强
   （而非扰乱）自我连续。

### C.5 结构性矛盾：决策台账可能成为绕过删除的副本（采纳为 P8 前必决开放问题）

矛盾：B.1 为"确定性重放"要求台账存产出卡内容；但隐私删除级联到记忆本时，台账里同一
份内容仍活着，台账即成删除旁路。

**代码与设计核实（2026-11-10）**：删除工具本期未实现——`src/api/index.ts` 仅有
`DeletedError`（"已删除"≠"从未存在"）语义预留，真源当前无 tombstone；冻结面
`frozen-surface.ts` 预留了 `erase` 符号并注明"删除是 append-only 的唯一例外"。设计稿
§4.25 已定原则：`persona_forget` 删除须令记录/派生/缓存/字节**全部清理、依赖闭包验证
无残留、tombstone 防重新派生，独立引用不误删**；垃圾桶 30 天反悔、之后转痕、180 天清除、
留痕不含被删内容。

两个候选（**v1.0 已裁决：采方案②，见 E.6-D4**；以下为当时的候选记录）：

- **方案①**台账随卡一起 tombstone：被删条目的重放降级为重推理并显式记录例外。缺点：
  决策链断裂，难审计"曾基于什么做过决策"。
- **方案②（倾向）**台账只存**指针 + 内容哈希 + 模型版本/理由**，不内嵌内容正文；内容
  留在可被 tombstone 的存储。删除后命中指针会得到 `DeletedError`，确定性重放自然降级为
  "知道做过该决策、但内容不可恢复"——既不复活已删内容，又保留"曾存在后被删"的事实，
  正好契合"已删除≠从未存在"语义，也符合"正文只存一份 + 指针"的既有哲学。

权衡不可回避：隐私（可彻底遗忘）与可重建（能确定性回放）在此处天然冲突，没有两全，
必须显式选择放弃哪一边；该决策要与 §4.25 删除闭包统一设计，不能让 P8 先建错。

### C.6 下钻判据改为"事后确定性校验器"（采纳，修订护栏 10 的实现形态）

让模型在作答前自评"凭线索够不够"是开放判断、不可靠也难评测。倒置为：允许直接起草，
但草稿中的断言必须带类型标记（时间/地点/承诺/引语/数字）；确定性校验器逐条检查断言
是否已加载对应等级证据，缺失则定向批量补取、只重写该断言。于是"何时下钻"从事前
置信度规则变成封闭校验循环，护栏 10 的 provenance 校验即是校验器本体，失败模式从
"编造"降级为"多取一次"。与 B.3 的意图分级映射互补：意图映射做粗路由，事后校验做兜底。

### C.7 v0.4 优先级与共识

对方建议的落地优先级，我方认同：

1. **先做 C.2 漏召样本埋点**：零架构改动，立即产出 Q3/Q4/Q6 数据，是性价比最高的第一步；
2. **C.5 台账-隐私矛盾必须在 P8 实现前裁决**（v1.0 已定方案②，见 E.6-D4）；
3. **C.3 决定义务记忆在 v1 有没有真正的家**（独立约束表）。

四轮沉淀后不变的底线：真源 append-only 与 A 块冻结面不动；记忆卡/叙事线/台账/约束表/
实体/权重全部是可重建投影且受 §4.25 删除闭包约束；重要度不写真源；客观档案不被
第一人称代笔污染；v1 工程刻意保守（平坦平凡检索、向量最后、删除与 P8 先想清再建）。

## 附录 D：第 4 轮外部评审意见与处置

来源：DeepSeek 网页版（2026-11-10，用户转发并提示可能降智）。我方逐条独立核实，未发现
需否决项，关键主张与现有代码事实吻合；但其引入概念较多，统一在 D.10 加"防过度工程"约束。
总主张：记忆本明确降格为**可重建的召回索引投影 + 窗口装配输入**，不再是"事件卡集合"。

### D.1 记忆本重新定位（采纳）

记忆本不持有需要人工判读的独立语义，它是召回索引与装配输入；语义正文唯一权威在真源、
叙述摘要唯一权威在记事本。至此"摘要版 vs 关键词版"的存储形态之争在概念上终结，工程
投入集中到装配、校验、删除闭包、评测四件事。

### D.2 线索三分离（采纳，物理实现允许合并）

| 投影 | 职责 | 进窗口 | 进 FTS | 生命周期 |
|---|---|---|---|---|
| display_cues 展示线索 | 2–3 锚词/类型标，给她看 | 是 | 可 | 稳定、有预算、少变 |
| retrieval_aliases 检索别名 | 同义/情境/用户真实查询措辞，供召回 | 否 | 是 | 增量、带来源/时间/敏感级/命中统计、有上限去重 |
| discriminator 区分句 | 回答"与同实体其他事件如何区分"（非"发生什么"） | 否 | 弱 | 存储态确认用、可重建 |

- 修正 C.2：漏召回填**只进 retrieval_aliases，不进 display_cues**，杜绝回填刷屏/污染。
- Q1 改用**区分度**而非字数回答：discriminator 能否让目标在同实体/同话题 top-k 中被唯一
  选中；区分不足就修 discriminator，而非加长叙述。与 DRM 负样本探针直接配套。
- 我方约束：三者是**同一记忆投影上的三类字段**，v1 不强制三张物理表，避免基础设施膨胀。

### D.3 权威指针锚真源，事件 UID 降为缓存（采纳，修正 B.1）

记忆卡权威字段存 `source_anchor`（真源轮次/经历 id、原文 span），事件 UID 仅作可丢弃的
解析缓存（可另建旧 UID→新 UID 重定位投影，同样可重建）。回跳先由锚点解析当前事件再读
摘要，解析不到则降级直读原文，不卡死；删除时 tombstone 锚点即级联失效。事实依据：真源
经历 id append-only 不可变，而事件 id 属可重算投影（真机事件 `anchors` 已指向经历 id）。

### D.4 gist 去权威化、可缓存重建（采纳，修正护栏 1）

持久字段只留：选择决定 + source_anchor + 三类线索 + 类型/实体/时间/敏感级。gist 改为
**可丢弃渲染缓存**——窗口装配时按锚点从记事本批量取摘要并确定性截断（护栏 3 的批量取回
已支持），缓存须标注可重建并受删除闭包约束。防撞词职责由**持久的 discriminator**承担
（它提供记事本没有的增量信息：差异，而非重复叙述），把"正文只存一份"贯彻到记忆层。
代价：摘要投影重建中窗口暂缺叙述，属可接受的临时降级。

### D.5 事后校验 + 竞争候选比较双保险（采纳，补强 C.6）

强断言（原话/日期/数字/承诺/敏感/否定）校验时，除证据等级外还须**比较 top-2/3 竞争候选
的 discriminator + 摘要头**；规则化为：候选冲突时分数再高也强制比较，唯一锚点明确时可
摘要确认。**否定/缺席型断言**（"没去过 X""没答应 Y"）不能靠存在性线索证明，必须经
约束表或时间轴穷尽兜底。失败模式仍为"多取一次"而非"编造"。

### D.6 约束表两级 + 冲突裁决顺序（采纳，细化 C.3）

- 硬约束/禁止型：短、每轮注入、不参与排序、优先级最高；
- 条件义务/记住型：带触发条件/作用域/失效/来源指针，P3 前用确定性关键词匹配触发，
  不常驻全文。
- 裁决优先级：安全与显式禁止 > 当前有效义务 > 身份叙事线 > 记忆卡 > 普通线索。
- 约束表在**召回后、装配前**强制过滤（防止约束词作为别名仍被召回，见 D.9）；改主意走
  supersedes/失效不物理删除；整表可从真源重建、受删除闭包约束。

### D.7 双台账、删除闭包先于 P8、以及漏召埋点本身是隐私旁路（本轮最高优先采纳）

- 台账细化为双份：可删除内容台账随卡 tombstone；不可删除的**审计事件**只存操作事实
  （decision_id/时间/操作类型/内容哈希承诺/指针），不存正文，命中即 `DeletedError`。
- 工程顺序调整：**先写删除闭包规范（级联到卡/别名/缓存/台账/叙事线/约束表/漏召样本的
  tombstone 语义），再建 P8**，防止先建错返工。
- **前三轮共漏的新隐私旁路**：C.2 漏召埋点会复制用户真实查询措辞。规定漏召样本只存
  规范化词/哈希 + 目标锚点 + 时间 + 命中统计，**不存完整敏感查询**；敏感查询不进
  retrieval_aliases；删除级联覆盖别名与漏召日志。

### D.8 目标函数可计算化（采纳）

- "一次正确回忆" = 断言级 provenance 全覆盖 + 竞争比较通过 + 未被用户质疑纠正（或离线
  金标命中）。
- 成本分五项分别报：窗口常驻 + 批量取回 + 下钻补取 + 重写 token，以及 P95 延迟，不只报总量。
- 四主指标：证据召回率、错误事件认定率、叙事/自我一致性、单位正确回忆成本。
- 影子评测可切换的"低价值事件"给客观定义：不影响断言 provenance、不涉义务、不涉身份叙事。
- 金标分层（主动冷回忆 vs 伴侣引发）+ 未 surfaced holdout 沿用 C.4。

### D.9 新增失败模式（采纳为工程约束）

1. 别名回填污染（错误前提/敏感）→ 别名带来源/有效期/敏感级，敏感不进展示线索；
2. 热门事件垄断窗口 → 槽位加同实体去重 + 同话题多样性配额，非单纯相关度排序；
3. 时间指代错配（"上次/那天"）→ 窗口态带相对时间标，时间轴兜底常开；
4. 约束被别名绕过 → 装配前强制过滤（并入 D.6）；
5. 批量取回溢出 → 候选数预算 + 摘要头截断 + 超预算只取 discriminator。

### D.10 我方防过度工程约束（对外审概念膨胀的总闸）

本轮新增三类线索、双台账、两级约束、多槽位等概念，目标形态完整但 v1 不得全量铺开：

1. 能作为同一投影内字段的，不新增物理表/服务；
2. 每个新构件必须能从真源重建、纳入删除闭包、并有对应评测指标，三者缺一暂缓；
3. v1 只保留最小可用闭环（见 D.11），其余作为演进项登记，待评测数据证明必要再建；
4. 所有新增仍不破真源 append-only 与 A 块冻结面，重要度/情绪不写真源。

### D.11 v0.5 落地优先级（综合四轮，更新为三件事）

1. **漏召埋点（按 D.7 隐私规范）+ 删除闭包规范**：零/低架构改动，先产 Q3/Q4/Q6 数据，
   且删除闭包先于 P8，避免埋点与台账成为删除旁路；
2. **线索三分离 + 指针锚真源锚点**：防记叉、回填污染、切分失配的结构性改造（同投影实现）；
3. **gist 缓存化 + 竞争候选比较校验**：不持久存第二摘要，强断言过 provenance + 候选比较。

五轮沉淀后的不变底线：真源与 A 块冻结面不动；记忆本是可重建、可级联删除的召回索引投影；
客观档案第三人称、不被第一人称代笔；v1 工程保守、评测驱动、概念不预先膨胀。

## 附录 E：第 5 轮外部评审意见与处置（收官·减法与反共识）

### E.3 四个四轮共漏盲区（处置）

1. **写入侧 ROI 缺席（采纳）**：复盘产卡/线索/discriminator/台账本身是 LLM 开销且最少
   被审视。新增指标 **单卡写入成本 ÷ 生命周期命中次数**，反向约束"给哪些事件产卡、产多重"，
   零命中卡的写入即纯浪费，纳入复盘选材评估。
2. **discriminator 缺修复闭环（采纳）**：最佳区分句取决于未来哪些事件撞词，复盘时同样
   不可知（与线索老化同源悖论）。补对称回路：DRM 探针检出区分不足 → 触发该卡 discriminator
   重写 → 写决策台账留痕，不只检测不修复。
3. **会话内已激活记忆状态缺失（采纳，归运行时）**：新增"本会话已展开记忆集合"这一
   **易失运行时状态**（不进真源/投影），同一 session 内已下钻讲述过的事件不重复召回/
   下钻，追问直接复用上下文；属槽位窗口的运行时职责。
4. **"部分不可重建"上升为原则（采纳）**：隐私删除是 append-only 唯一例外，级联删除后
   "一切投影可从真源重建"对被删部分不再成立。显式定义系统进入**合法的部分不可重建态**，
   每个投影须写明此态下的降级语义（命中指针→DeletedError→"曾存在后被删、内容不可恢复"），
   不再假设真源永远完整。
5. **冷启动/迁移（事实澄清）**：当前**记忆本尚不存在**（仅有事件二级真源投影，无任何
   selection/权重字段，已核）。故无存量迁移负担，首批记忆卡直接从事件投影 + 真源离线
   批量构建即可，真源不丢、构建可重跑；未来若换形态同理重建。

### E.4 两条反共识挑战的裁决

1. **在线确定性校验器降级（采纳）**：断言结构化 + 类型→证据封闭映射 + 缺失重写循环，
   工程量与实时延迟在几百卡系统上可能远超收益，且断言粒度的封闭性本身可疑。v1 改为
   **离线对采样回答做 provenance 审计**（拿到真实编造率/误认率信号），在线不做重写循环；
   待审计证明"编造渗入语气"高频越线，再上在线校验。
2. **叙事线正名为核心资产（采纳，消解 D.1 不自洽）**：记忆本既为纯召回索引，"故事感/
   自我连续"便全部落在叙事线上，它不再是护栏 6 的"补充"而是**单点**。明确叙事线与检索
   层为并列的两大核心职能（一个管"找得到"、一个管"她是谁"），给予同等工程与评测优先级
   （自我一致性探针随之升为一等指标）；第一人称语态仍守 B.3 边界——仅限她自己的
   reflection 产物，不污染第三人称客观档案。

### E.5 替代架构"不建独立记忆本"的裁决（部分采纳；D1 已拍板，见 E.6）

对方主张：在事件投影上直接加 selection flag + 权重 + 线索字段，消灭"卡↔事件↔真源"
三层副本。动机正确（正文只存一份），但**经代码核实不能照抄**：事件是**二级真源，写入即
固化、不允许算法批量重算、备份级别等同真源**（B 块 §4）；而记忆选择/权重/别名回填是
算法持续调整、可重建、高频变化之物，并入事件本体会污染其固化纪律。

我方折中方案（D1 已拍板采纳）：**不建含叙述正文的记忆卡集合（消灭第二份摘要副本，采纳其
减冗余内核），但保留一个极薄、不含任何正文、挂 source_anchor 的"记忆选择索引投影"**
（selection 标记 + 权重 + 三类线索字段，全可重建、可回填、受删除闭包约束）；事件摘要
正文仍只存事件二级真源一份。约束表、叙事线、未来 facts 等**非事件粒度**单元无法挂事件行，
仍保留独立投影。既拿到减副本收益，又不破坏二级真源，也给非事件记忆留位。

### E.6 五轮收口：D1–D5 决策基线（2026-11-11 用户拍板）

五轮外审的分叉已全部定案。除 D4 触及真源删除语义、难回头外，D1/D3/D5 均为投影层决策，
可经重建投影纠正，试错成本可控；D2 不拍常数、定机制。

**D1 记忆层物理形态 —— 定：极薄"记忆选择索引投影"。**
不建含叙述正文的记忆卡集合，只保留零正文、挂 `source_anchor` 的薄索引（selection 标记 +
权重 + display_cues/retrieval_aliases/discriminator 三类字段，全可重建、可回填、受删除
闭包约束）；事件摘要正文只存事件二级真源一份。否决"字段并入事件投影"（污染二级真源
固化纪律，见 E.5）与"独立完整记忆卡"（正文副本冗余）。约束表、叙事线、未来 facts 等
非事件粒度单元保留独立投影。

**D2 质量红线与预算 —— 定：先观测、后定硬阈值，不拍伪精确常数。**
v1 头一期红线只观测、不拦截，用真实回忆情节跑出各指标分布，再把硬门槛设在"略低于当前
可靠水平、能挡住明显劣化"处，阈值每次调整进决策台账留痕。观测期占位经验值（非物理常数，
待 harness 校准）：证据召回率下限 0.85；错误事件认定率上限 0.05（记叉比漏记更伤信任，
强断言/承诺/日期/原话/否定场景趋近 0）；叙事/自我一致性下限 0.8，且尺子未校准前只观测
不卡发布。预算用结构性表达而非 token 常数：**工作窗口 700 字封顶、单轮至多一轮补取**，
P95 只测上下文装配路径。

**D3 叙事线定位与语态 —— 定：与检索层并列的核心资产，语态分层。**
叙事线承担"她是谁"的身份连续职能，给同等工程与评测优先级，自我一致性探针升一等指标
（初期只观测）。事件摘要保持客观第三人称；第一人称现在时仅限她本人 reflection 产出的
叙事章节，且每章挂真源锚点、可核验、禁止凭空生成，不污染客观档案。

**D4 删除原则与台账 —— 定：方案② + "合法部分不可重建态"立原则，删除闭包规范先于 P8。**
台账不存正文，只存指针 + 内容哈希 + 模型版本 + 理由；分双份——内容台账随卡 tombstone，
审计台账仅留操作事实（decision_id/时间/类型/哈希承诺/指针）、不可删。删除命中指针返回
DeletedError，语义为"曾存在后被删、内容不可恢复"（已删除 ≠ 从未存在）。删除闭包级联
覆盖卡、三类线索、渲染缓存、台账、叙事线、约束表与漏召日志；漏召埋点只存规范化词/哈希 +
锚点 + 时间 + 统计，不存完整敏感查询。**工程时序：先写删除闭包规范，再建 P8 台账。**

**D5 v1 范围 —— 定：E.2 五件套 + kill list，演进项一律数据触发。**
v1 只做平坦 BM25+IDF（含近因先验）、类型化轻卡（锚真源、无正文副本）、source_anchor
锚真源且事件 UID 仅缓存、槽位制窗口、离线 sampled provenance 审计。向量、实体倒排、
线索三分离物理化、在线断言重写校验器、双台账完整版、约束表两级化等全部挂起，待对应数据
越过红线再建。未来实施的第一步是**隐私合规版漏召埋点 + 离线 provenance 审计**（零架构
改动、先产出 D2 定阈值所需基线）；本稿仅定设计，产品代码开工另行启动。

### E.7 五轮不变的最终底线

真源 append-only 与 A 块冻结面不动；事件二级真源写入即固化、不被算法重算；记忆侧一切
新增均为可重建投影并受删除闭包约束，删除后进入有明确定义的部分不可重建态；重要度/情绪
不写真源；客观档案第三人称、不被第一人称代笔；v1 刻意做减法、评测驱动、阈值先行、
概念不预先膨胀。
