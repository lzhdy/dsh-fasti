## 1. 总评

问题诊断成立：trigram（固定三字符切分）＋3 码点准入下，任何 2 字中文词在索引里结构性不存在，这是索引单位选错而非参数未调好，charter §0 的定性正确。bigram 滑窗＋phrase 匹配＋原文复核是 CJK 检索的成熟路线，探针增益（9/25 → 22~23/25）方向可信。窄卡边界切得对：整句片段枚举外移、三参数留待金标标定、真源零改动、升版走库级 v3 沿用 E-6 先例，均无异议。

未找到推翻方案的 Blocker。两个 Major 都不是设计错误，而是**探针口径与生产语义之间的等价性缺口**——即"验收数字能不能代表出货路径"的问题。这类缺口若带进 TDD 阶段，会在红测落地时被迫回头改 charter，等于把歧义留到最贵的阶段，故要求冻结前闭合。

## 3. Major

### M-1　unigram 双写规则两读，且验收两个数字疑似不同臂

**位置**：§2.1 目标 1／目标 4、§3 步骤 4、§5 红测 3、§6 验收第二条、E-8。

**理由**：

1. **规则两读**。"CJK 单字以 unigram 双写补底"存在至少两种读法：
   - 读法 A：仅孤立 CJK 字（run 长度为 1）补写 unigram；
   - 读法 B：所有 CJK 字全部 unigram 双写。
   两读的索引体积（读法 B 约 3× 而非 2×）、token 可达性、召回面均不同。§5 红测 3"单字 unigram 补底"同样两可，红测无法锚定实现。

2. **生产可达性矛盾（核心）**。目标 4 将 FTS 准入阈值定为 `MIN_FTS_CODEPOINTS = 2`，单字查询被挡在 FTS MATCH 门外。若读法 A 成立，则 unigram token 在生产路径上基本不可达——只有 ≥2 码点且恰好含孤立单字的查询才摸得到它。探针的 22→23 那一分，很可能是某个单字 oracle 词在**无门禁的探针环境**下拿到的；生产口径复现不了。验收写"离线复跑探针口径 ≥23/25"，字面上能过，但度量的不是出货路径。

3. **数字疑似不同臂**。23/25 来自 bigram+unigram 臂；1.95×（239→467 字符）的构成（含不含 token 间分隔符、含不含 unigram 双写）文中未载。若含全字双写，字符数应明显高于 2×，故 1.95× 与 23/25 很可能不是同一臂的度量。两个验收数字不同源时，±10% 偏差门无意义。

4. **脱敏复现未定义**。挂账①载明探针语料含真名、入库前统一脱敏。脱敏改字长即改 bigram 结构（两字名→三字名直接改变滑窗产物），脱敏后语料能否复现 22/23 未定义。

**处置建议**：

- toBigramUnits 规则以三行钉死：unigram 触发条件（建议读法 A）、查询侧是否/如何发射 unigram token、token 间连接符（含它是否可被查询侧误命中）。
- 指认 22→23 的那一个词，说明它在 `MIN_FTS_CODEPOINTS = 2` 门禁下的实际路径；据此二选一：
  - 验收改走**生产路径 mini-bench**（门禁＋复核全开，取生产语义数字）；或
  - 在 charter 明示探针口径的局限（无门禁、无复核），并说明为何仍采信。
- 登记"脱敏后语料复现基线"为验收前置或挂账，二选一写明。

### M-2　归一化（NFKC／大小写／组合方式）三侧一致性未钉死，存在两条具体回归窗口

**位置**：§2.1 目标 5、§3 步骤 4、§5 红测 1。

**理由**：

1. **NFKC 回归窗口**。红测 1 列"NFKC 全半角"，说明 toBigramUnits 拟做 NFKC 归一化。而目标 5 把复核对象改为**原始 cue/别名文本**——若复核 haystack 用未归一化的 `display_cues_json` 原文，则"存储为全角、查询为半角"（或反向）的样本，现行 trigram 管线若不做 NFKC（E-1~E-5 未记载）今天 raw-to-raw 反而能命中；本卡改后变成 FTS 命中→复核拒收的**静默假阴性**。且探针口径验收不经过复核门，此回归在验收里测不到，只在真人使用时暴露。

2. **大小写回归窗口**。阈值 3→2 使 2 码点 ASCII 查询从 LIKE 回退路径（SQLite LIKE 对 ASCII 默认不区分大小写）迁入 FTS＋复核路径。unicode61 折叠大小写，若 matchesSubstring 区分大小写，则 "ai" 查 "AI" 从命中变落空——恰是本卡声称要改善的短查询类别。§3 步骤 4 写"LIKE 回退路径语义不变"，对这类查询字面上不成立（它们的路径本身迁移了）。此条对照 bm25.ts 现行实现十分钟可证；即便 ≥3 码点查询的同类错配今天已存在，2 码点查询的路径迁移是本卡新引入的回归面，无论如何需红测。

3. **两个顺带钉死点**：
   - 复核 haystack 的组合方式（逐 cue/别名字段独立复核 vs 拼接后复核）决定 cue 与别名拼接边界处的跨界 bigram 伪命中是被拦还是放行——两种选择都成立，但必须写死，且与 FTS 索引文本的拼接方式（E-5）对齐；
   - FTS DDL 中 tokenize 选项显式声明（如 `remove_diacritics` 取值），不依赖 SQLite 默认值；
   - "码点"按 Unicode code point 还是 UTF-16 code unit 计（astral 字符两说），一句话定死。

**处置建议**：抽一个共享 normalize 纯函数，写入侧、查询侧、复核侧三侧同源调用；红测 1 增加"查询形态 ≠ 存储形态"矩阵（全/半角、大小写、2 字 ASCII、跨界 bigram 四类），每格断言预期结果（命中或干净 miss，二选一写死，不留"未定义"格）。

## 4. Minor

- **m-1**（§7 风险表）"误召以探针 B2′ 基线 2 例为观察上限"是**臂错配**：B2′ 是片段枚举（拆句工）臂的成绩，本卡明确不做片段枚举，不能拿它当本卡误召基线。且本卡管线下词法误召按构造 ≈0（phrase 命中＋子串复核 ⇒ 复核必过），生产中观察到 >0 应按 bug 对待而非容忍带。
- **m-2**（§6 验收）"1.95×"度量口径未定义：哪个臂、含不含分隔符与 unigram、量的是 FTS 文本列长度还是库文件/页数。±10% 的门建在模糊基数上，先钉口径再设门（与 M-1 第 3 点联动）。
- **m-3**（§8 vs §9）"聚焦外审三问"与签认栏"外审五问"未对齐：五问（分歧／反对意见闭环／红灯／实测数据／最坏回滚）是闭环检查单、三问是内容问题？签认栏引用哪个清单需写明，否则签认无法逐项打勾。
- **m-4**（§5 红测 1）补"空 units 查询"一格：纯标点/空白输入经 toBigramUnits 得空数组，空 phrase 在 FTS5 MATCH 下的行为（语法报错还是空集）需红测钉死，并定义查询侧对空 units 的出口（走 LIKE 回退还是直接返回空）。
- **m-5**（§0、E-7/E-8/E-10）charter 自称"自包含，外审者无需读其他文档"，但关键证据（NTCIR-4 结论的出处与适用条件、探针方法学：25 个 oracle 短词与 16 句真人问法如何挑选、诱饵卡口径）全部落在不可外验的内部"学术稿"。"证据三方同向"里有两方外审只能采信。至少应附一段方法学摘要，或随 charter 附探针脚本＋语料清单（脱敏版）。

## 6. 对 §8 聚焦三问的回答

### 6.1 升版口径（FTS 几何变更走库级 v3、卡行版本不动）

**成立。** FTS DDL 属库级 schema；卡行形态未动（E-6 先例：v2 只改 mem_miss 也升库版本、卡行不跟）；row_hash_sum 逐字节相等验卡行、召回红测验 FTS，两套证据分工清楚。补上 Q-A（正向拒绝语义）与 Q-C（反向拒绝）两格后，未见迁移/漂移漏洞。

### 6.2 宽窄边界（片段枚举拆出本卡、留待金标标定）

**切分干净。** 本卡与拆句工卡的共享面恰好是纯函数（toBigramUnits）＋阈值门＋复核门，接口面明确；未发现本卡必须顺带解决的耦合面。两点建议：

1. Q-D 的函数分层现在决定（成本为零，事后重写成本高）；
2. "复核门不可绕过"建议登记为**两卡共享不变量**——拆句工卡将来的宽松聚合策略不得跳过原文复核，此约束写进本卡 charter 即可为后续卡立规。

另确认：把 FTS 阈值降到 1 以顺带支持单字查询的诱惑应当抵制——那会把 unigram 的查询语义、门禁语义整个卷进本卡，与 M-1 的钉死动作冲突。

### 6.3 时序（本卡先于 #123 解冻、先于 P6 出题）

**成立。** P6 出题后置尤其正确：trigram 会结构性误伤 S2/S3 换述层，bigram 落地后 P6 的索引几何前提才公平。#123 先后技术上无耦合（FTS 是写入时投影，重建机械，display_cues_json 接口面稳定）。建议把"v2→v3 拒绝窗口在真机仅 2 卡时成本最小，越晚越贵"这一论据写进 charter §4——这是本卡"现在做"的最强理由。未识别返工面。
