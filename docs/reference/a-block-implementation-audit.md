# A 块阶段 0–2 · 实现前文档审计与验收清单

> **审计方立场**：实现方是未参与本项目讨论的外部 AI，只看文档、不看过程稿。本审计站在它的视角，找出会让它"卡住或靠猜"的歧义、缺口与内部矛盾，逐项给出建议口径；并给出阶段 0–2 的验收清单，作为实现完成后代码审计的同一把尺子。
>
> **审计对象**：`docs/a-block-final-design.md`（725 行，定案稿）。
>
> **结论先行**：定案稿主体自洽、可实现，但有 **1 项必须用户先拍板（数据根）**、**11 项需补明确口径**、**4 项可由实现者自定后评审对齐**。这些不澄清，外部实现者大概率在 ULID、幂等、FTS 来源、指针→边映射等处靠猜，返工概率高。

## 一、必须先拍板（阻塞实现起步）

### 1. 新仓库的数据根路径（定案稿内部矛盾）

`a-block-final-design.md` §18.3 写明"新仓库不读写、不迁移 `~/.dsh/persona-innate`"，但任何新代码都必须有一个数据根来落真源——这两者冲突。阶段 0–2 开发期确实不碰真实目录，但阶段 3 转写必然要读旧目录、写新目录。

| 方案 | 数据根 | 代价 |
|---|---|---|
| A | 新根 `~/.dsh/fasti/`，阶段 3 转写迁入，旧目录留作备份 | 目录改名、需一次性转写；但干净、与插件 id 一致 |
| B | 沿用 `~/.dsh/persona-innate/` | 零迁移；但目录名与新插件不符，且字面违反 §18.3 |
| C | 可配置，默认 `~/.dsh/fasti/`（显式配置 > `$DSH_HOME` > 默认） | 灵活，工程上最稳 |

**审计推荐 C**：路径解析三级逻辑（显式配置 > `$DSH_HOME` > 默认）本就是旧项目踩坑结论，可直接复用；默认新根与 `dsh-fasti` 同名，旧目录在阶段 3 转写验证无误前整体保留为备份。**此项需用户确认。**

## 二、需补明确口径（我给出建议，确认后并入定案稿）

### 2.1 阶段 0 · 契约层

| # | 缺口 | 外部实现者的困惑 | 建议口径 |
|---|---|---|---|
| 2 | ULID 来源 | 生产 dependencies 为空，不能 `npm i ulid`；自己写又怕单调变体写错 | **自实现单调 ULID**：128bit = 48bit 毫秒时间戳（Crockford Base32 前 10 字符）+ 80bit 随机熵（后 16 字符）；同一毫秒内随机部分单调递增；时钟回拨时不产生比上一条更小的 id。配时钟回拨专项测试 |
| 3 | 原语签名 | §9 只给原语名与说明，无参数/返回/抛错约定，阶段 0 无法"先写契约" | 补一份 `.d.ts` 级原语契约：明确每个原语的入参类型、返回类型、同步/异步、错误抛出约定（缺指针/越界/坏哈希一律抛错，不返回空） |
| 4 | Pointer.seq 语义 | 行号从 0 还是 1？区间端点含不含？ | seq 从 **0** 起算；`[a,b]` 为**闭区间含两端**；单 number 表该行；`resolvePointer` 越界或缺失即抛错 |
| 5 | schema_version | 数字字面量如何校验、未知字段怎么处理 | 写入时记录当前版本号；读取器对未知字段原样保留（C2），不丢弃不报错 |

### 2.2 阶段 1 · 真源层

| # | 缺口 | 外部实现者的困惑 | 建议口径 |
|---|---|---|---|
| 6 | `raw/<channel>/` 行格式 | 文档说"新通道统一格式"但没给 schema | **沿用 RawTurn 8 字段**（event_id/session_id/turn_id/speaker/raw_text/asserted_at/ingested_at/content_hash），event_id 在通道命名空间内唯一；逻辑单一原文层、物理按通道目录 |
| 7 | experiences 幂等键 | schema 无 sourceKey/dedupKey，"append 幂等"靠什么判断 | **以 `id` 为幂等键**：重复 append 同 id 视为重试，返回既有条目、不重复写、不报错；raw 层 append 无去重（继承旧契约），调用方按 content_hash 自查 |
| 8 | 初始 channels.json | 空文件起步还是预置 dsh？ | 首次初始化**预置 dsh 通道描述符**（已注册的第一个通道）；其余通道由适配器 `registerChannel` 追加 |
| 9 | tick 起步 | 无运行态时如何分配不重复 | 从真源 experiences 读 `max(tick)`（投影不可用则扫分片）+1；与 §8.1 自愈一致 |
| 10 | 单写者实现 | "同一写队列"是内存锁还是进程锁 | 阶段 0–2 按**单进程 Promise 串行队列**；跨进程锁预留不实现，归 E（§15-6） |

### 2.3 阶段 2 · 投影层

| # | 缺口 | 外部实现者的困惑 | 建议口径 |
|---|---|---|---|
| 11 | FTS 文本来源 | 正文走指针不内联，FTS5 的 `text` 列索引什么 | 投影构建时经 `observation.text` 指针**回原文提取可检索文本**，叠加 `observation.cue` 灌入 FTS；索引的是原文+线索，不是摘要 |
| 12 | pointers → edge 映射 | experience.pointers 如何进入 edge 表，文档未写 | append 时把 `pointers[]` 折叠进 edge：src=experience.id、predicate=Edge.type、dst=target、valid_ms=occurred、created_ms=recorded；判断期因果边（4.20）同表不同 predicate，由反思经历投影 |
| 13 | 投影增量 vs 全量 | 日常 append 后投影怎么更新，与 §7.3 全量重建何关系 | 写者队列内 append 真源后**同步增量更新投影**（L1 用事务，失败回滚并标记需重建）；§7.3 全量重建仅用于损坏/schema 升级/对账 |
| 14 | 引擎降级检测 | 如何判定 node:sqlite 被宿主禁用 | 动态 `import('node:sqlite')` 包 try/catch，导入失败或运行期抛模块禁用错误 → L2；L2 索引损坏 → L3；降级状态写检查点并在注入时标注 |

## 三、可由实现者自定，评审对齐

| 项 | 已知约束（减少实现者决策面） |
|---|---|
| TypeScript 配置 | 沿用旧 tsconfig：`target ES2022` / `module NodeNext` / `strict` / `declaration` / `outDir lib` |

| L2 JSONL 索引布局 | 最小要求：时间索引、通道索引、词法倒排三类；具体文件名实现者定，评审确认无遗漏 |

### 阶段 1 · 真源层

- [ ] 原文层：raw-turns 与 raw/&lt;channel&gt;/ 同构（8 字段），append-only、无去重
- [ ] 结构层：experiences 按月分片 + manifest，append 以 id 幂等（重复 id 不二次写入）

- [ ] tick 单调、乱序到达时 tick 与 occurred_at 允许不一致（§5 语义）

### 阶段 2 · 最小投影

- [ ] experience / edge / experience_fts 三表 + 索引建立，字段与 §7.1 一致
- [ ] FTS 文本来自原文回读 + cue（非摘要），trigram 中文可命中
- [ ] experience.pointers 正确折叠进 edge，predicate 与来源一致
- [ ] 增量投影与真源在事务内一致；强制失败后可触发重建
- [ ] L1→L2→L3 降级可手动触发验证，每级功能不丢、仅性能/丰富度下降，降级有标注
- [ ] 全量重建后对账：RawTurn 数 = dialogue 经历数；media 数 = asset 数；各通道 count 与 channels.json 一致
- [ ] `npm run build` 通过；`node --test` 全绿，覆盖 legacy-behavior-contract 第三节边界

## 六、代码审计的工作方式（审计方承诺）

**实现方交付时需提供**：可访问的仓库（git 地址或放入项目目录）、对应 commit、`npm run build` 结果、`node --test` 结果、一份实现说明（关键决策、偏离定案稿之处及原因）。信息不全则审计不开始，避免在猜测上下文中下结论。

**审计问题分级**：

| 级别 | 含义 | 处置 |
|---|---|---|
| Blocker | 违反冻结面/红线/数据完整性 | 必须改，否则不通过 |
| Major | 与契约不一致、关键边界缺测试 | 应改 |
| Minor | 可读性、简化、约定统一 | 建议改 |
| Question | 需实现方澄清 | 确认后归类 |

审计只产出问题清单与依据（条目 + 位置 + 定案稿对应条款），**不直接改代码**；修正由实现方完成，回到审计方复核，直至 Blocker/Major 清零。
