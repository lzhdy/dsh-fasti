## 0. 一页结论摘要

### 0.1 问题一：已完成代码哪些真该调整（最关键 5 条）

1. **P0 = 0。没有发现真源被绕过、二级真源被算法重算、数据损坏一类缺陷。**【事实】三层真源
   唯一写出口是 append，全文无 update/delete 出口（`src/source/experience-log.ts`、
   `raw-log.ts`、`event-log.ts` 静态扫描）；事件重建只认 events 真源、不重跑切分
   （`src/projection/rebuild.ts:110-125`）。五条冻结面与「写入即固化」纪律在代码层兑现。
2. **P1 = 2 且同根：切分器与修正器之间没有状态接线。**【事实】她 reopen 已闭合事件后，
   切分器不接管，该通道下一条摄入会造出同通道第二个 open 事件，重启 `restore()` 即抛
   CorruptedError、事件层整体 Unavailable（`src/api/index.ts:1021-1027`、
   `src/event/segmenter.ts:227-271`、`src/api/index.ts:830-841`）；对正在 open 的事件做
   merge/split 后，切分器持退役 eventId 继续并入，会在退役版本链上复活写新版本
   （`src/event/correction.ts:495-496` 自注未处理、`src/event/segmenter.ts:515-583`
   无退役态守卫）。修复面只在切分器/门面的进程内状态，**不碰真源、不碰二级真源**，
   但改变她修正 open 事件的语义，标注**需用户批准**。
3. **契约写边界有一处注释与实现漂移（P2）。**【事实】`parseExperience(write)` 头注释声称
   拒收未知字段，实现把未知顶层键无条件拷回（`src/contract/validate-experience.ts:394`
   vs `:508-512`），禁字段名只查顶层（`:399-405`），严于它的 event 契约是递归检查
   （`src/contract/event.ts:470-481`）。当前唯一写入方是门面固定形状输入，运行期影响≈0，
   属防御 invariant 名不副实，不是活跃缺陷。
4. **调研报告十个外部反面教材逐项反向核对，结论全部「已规避」或「预留期不适用」。**【事实】
   无裸删、无纯 ADD 矛盾并存、检查点是白盒 JSON 非黑盒 BLOB、session_id 只在原文层冻结
   八字段、情绪/重要度零入内核、摘要失败有三态退避与三处可观测计数而非静默吞、无默认遥测、
   无 LLM 原地重写；删除闭包因 erase 尚未实现处于白纸期，DeletedError 三态分叉位已留。
5. **其余 P2 约 8 条全部建议维持现状或仅在投影/切分器层微调**（frozen-surface 四条硬编码
   ok:true、静默补判世界轴/系统轴口径分叉、exhausted 事件开机重入队、L2 全量刷索引、
   投影无 schema 版本表、reviseBoundary 后计数器不重算等），没有一条需要动冻结面。

### 0.2 问题二：值得新加/借鉴什么（最关键 5 条）

1. **最该立刻吸收的是廉价工程件而非新存储**：Mem0 候选序号化防幻觉（调研报告 §4.3、§10.1
   第 2 项）落 v1 半自动种子卡与未来一切 LLM 接口；LlamaIndex/AstrBot 槽位预算 waterfall

2. **Graphiti 双时序失效纯函数（调研报告 §4.1、§5.3）确认可落地**：本项目 edge 表四字段与

   写法应严格复刻「LLM 只出候选、确定性纯函数裁决、旧行置失效不物理删」，先用于选择索引的

3. **C 块（主动性、回复管线）模式选型已被调研充分支撑且不动内核**：主动=带 initiation
   标记的合成轮走同一管线（AstrBot/MaiBot）、两层防打扰（MaiBot 概率门+只收紧不放宽+
   退避）、非常驻 SQLite 任务表借 Letta 状态机字段而不要常驻 tick、两遍生成借
   MaiBot Planner/Replyer。枚举位 `her/system/environment` 已在契约内，无需改真源。
4. **roadmap 既有排序被调研加强而非推翻**：删除闭包先于 P8（D4）、向量/实体倒排数据触发
   （D5）、queryEntity 随 P3、媒体层随阶段 3+、tick 去中心化是三端互通前唯一内核预留项——
   外部样本（Kuzu 嵌入式弃用、15 容器 Dify、langgraphjs 无本地 SqliteStore）全部支持继续
   克制，没有发现需要把 kill list 项目提前的证据。
5. **「虽流行但仍不做」清单必须显式保留并写清重议触发条件**（见 §2.2）：向量/图硬依赖、
   常驻调度器、真源原地更新或 LLM 静默改写、黑盒检查点、情绪数值入契约、在线校验器等，
   每项给出量化数据触发条件，防止调研热度把五轮外审已 kill 的东西带回。

### 1.2 P1 详条（修复均不触冻结面，但需用户批准）

#### 1.2-A reopen 后切分器不接管，可致重启后事件层 Unavailable

- 【事实】`reopen()` 只在事件真源追加一个 `status:'open'` 新版本（`src/event/correction.ts:441-458`）；
  门面 `reopenEvent` 执行后只调 `syncEventProjection()`，不通知切分器
  （`src/api/index.ts:1021-1027`）；merge/split/revise 四个修正入口同构，均无切分器回调
  （`src/api/index.ts:987-1039`）。
- 【事实】切分器每通道 open 状态存内存 `openByChannel`；通道无 open 条目时规则 2 直接新建
  事件（`src/event/segmenter.ts:227-232`）。reopen 发生在事件已闭合、该 map 条目已删除
  之后，故该通道下一条摄入会新建第二个 open 事件；`restore()` 发现同通道两个 open 即抛
  CorruptedError（`src/event/segmenter.ts:270-271`），门面启动捕获后把事件层置
  Unavailable、记录本照常读写（`src/api/index.ts:830-841`）。
- 【事实】现有测试只验证 reopen 的版本与状态翻转（`tests/api/event-primitives.test.ts:283-285`、
  `tests/event/correction.test.ts:340-348,559-577`），没有「reopen 后同通道再摄入」的
  集成用例，故 504 测试全绿未暴露此路径。
- 【推断】影响边界：仅由她手动重开事件触发，正常摄入不触发；后果是事件原语 Unavailable
  而非真源损坏，且不影响记录本，属可恢复的可用性事故，定级 P1 而非 P0。
- 【建议】二选一，均为进程内状态接线、不写任何真源：①门面在 reopen 成功后调用切分器
  新增的「接管 open 事件」入口（从事件行重建 OpenEventState，restore 已有等价构造逻辑可
  复用，`src/event/segmenter.ts:254-289`）；或②reopen 前校验该通道是否已有在途 open，
  有则抛 ConflictError 要求先处理。补三条集成测试（reopen 后再摄入不新建、重启 restore
  通过、修正后 openByChannel 指向正确）。**需用户批准**（改变手动修正的运行时语义）。

#### 1.2-B 对正在 open 的事件 merge/split 后，切分器在退役链上复活写版本

- 【事实】`correctableEvent` 允许 open/closed 事件被修正、只拒绝 merged/split/archived
  （`src/event/correction.ts:484-490`）；修正器 `retire()` 注释自承「若切分器仍持有该
  事件的 open 状态，追加前需自行跳过——那是切分器一侧的跨卡事项」
  （`src/event/correction.ts:492-497`）。
- 【事实】切分器 `mergeInto` 直接 `currentOf(state.eventId)` 后展开追加新版本，全程不检查
  current.status 是否已是 merged/split（`src/event/segmenter.ts:515-583`）；事件日志
  appendVersion 的写前校验只查分片 seq 与外部写入，不查事件状态（`src/source/event-log.ts:193-210`），
  没有底层拦截。
- 【推断】于是 open 事件被 merge/split 退役后，后续同通道摄入会以退役 id 再 append 一个
  open/closed 新版本，退役版本链被复活、split_into/merged_into 语义被打断，同样会在
  restore 或 owner 计算时产生不自洽。与 1.2-A 是同一个缺口的两面：修正器改了真源当前态，
  切分器内存态无人同步。
- 【建议】与 1.2-A 同一改动收口：门面在任一修正成功后，按事件当前态重算该通道
  openByChannel（退役则清除并按 split_into/merged_into 指认新主，或该通道暂无 open 则
  删条目）；mergeInto 入口加一道防御：current 已退役则抛 ConflictError 并接修复后的重算
  逻辑，不允许静默续写。**需用户批准**，配套变异测试（先拆掉守卫复现复活、再锁修复）。

### 3.2 六个外部机制的具体吸收写法

#### (a) Graphiti 双时序失效纯函数 → edge 表与 discriminator/别名失效

【事实】Graphiti 的机制是 LLM（dedupe_edges.resolve_edge）只返回 contradicted_facts
索引，`_apply_temporal_invalidation` 用无 LLM 纯日期窗口比较落库，旧边同 uuid MERGE SET
expired_at 不删除（调研报告 §4.1，commit e911422）。本项目 edge 四字段与 as-of 三条件
已具备且三档同口径，缺的只是「置失效」动作。

【建议】分两步，v1 只做第一步的投影内版本：

1. v1 选择索引投影内：实现一个无 LLM 纯函数
   `invalidateSelection(current, candidate, nowMs)`，输入为同一 source_anchor 主题簇的
   当前有效行与候选行，规则封闭可单测：区间不重叠→共存；候选区间明确接续且替换同一关系
   →旧行写 invalid_ms/expired_ms（时间语义复用 valid_ms=世界轴、created_ms=系统轴的
   现有约定，`edge.ts:46-53`），追加新行、不删旧行；任何需要语义判断「是否矛盾」的步骤
   只产出候选索引（人工确认或离线审计），函数本身不调模型。
2. facts 七态/edge 失效启用时：同一函数泛化到 edge 表，as-of 查询直接复用现有三条件
   （valid<=T、invalid>T、created<=T），不另造过滤语言——这正是针对 Graphiti 需调用方
   手写 DateFilter 短板的规避。discriminator/retrieval_aliases 的失效同行处理、同属可
   重建投影，删除闭包统一级联。
3. 全程不引入 Graphiti 的 LLM 建图非确定性：候选没有人工/离线确认前，默认什么都不失效
   （宁可并存，不可误失效），与 Mem0 纯 ADD 矛盾永久并存的区别在于我们留有显式失效动作
   与台账，而非依赖 prompt 自觉。

#### (b) Mem0 候选序号化 → 检索返回与 LLM 接口

【建议】所有把检索结果交给模型的环节（半自动种子卡、未来 C 块 Planner）统一协议：

1. 检索返回结构为有序候选数组，每项分配当次调用内稳定序号 `[1]…[n]`，服务端保留
   「序号→source_anchor」私有映射，正文/锚点 id 不直接暴露给自由生成环节；
2. prompt 要求模型引用事实时只能输出序号，输出未知序号、重复序号或无序号的事实断言，
   解析侧拒绝并降级为「多取一次」（对应外审 C.6 的失败模式降级，不产生编造内容）；
3. 种子卡半自动流程中，模型产出的 selection 决定经序号映射回 anchor 后再落投影，映射
   失败的条目整笔拒绝并计入审计埋点；
4. 该协议是接口规范不是新存储，v1 零依赖可实现，直接支撑 A1 与 provenance 审计。

#### (c) LlamaIndex waterfall → 700 字窗口装配的具体设计

【建议】参照 LlamaIndex block priority 与 AstrBot 两阶段压缩（调研报告 §7.2、§10.1-3），
结合 D2「用结构性表达而非 token 常数」：

1. 槽位：保底槽（系统指令/人格静态约束，priority=0 永不裁剪）、近因槽、身份槽（自我
   叙事线头章，D3）、相关槽（选择索引检索结果）、义务槽（v1 若无独立约束表则保留槽位
   预算与接口，不强行造表，对应外审 C.3/D.6 的渐进路线）；
2. 预算：700 字为硬顶，各槽给比例区间而非拍死常数，观测期从 harness 数据校准；装填
   顺序按 priority 降序、裁剪按 priority 升序（先牺牲相关槽尾部），任一槽裁剪保完整
   回合/完整卡片、不切半句；
3. 相关槽采用「3 张卡+1 份头名事件摘要」起点动态装填、不预设塞满（外审护栏 5），摘要
   按锚点从事件二级真源批量取、确定性截断，窗口态零模型往返；
4. 硬预算：单轮至多一轮补取、P95 只测装配路径（D2）；同实体去重与同话题多样性配额
   在外审 D.9 已列，v1 可先只做同实体去重这一条最便宜的。

#### (d) Letta MemFS 延迟生效与 cron tick/租约 → C 块调度边界

【建议】取语义不取实现：

1. 「记忆编辑下轮编译才生效」在本项目不需要专门机制：选择索引/别名/权重都是可重建
   投影，编辑后下一次窗口装配自然读到新值，当轮已装配上下文不回改——把这条写成显式
   语义约定即可，防止未来有人做成当轮热替换导致同一轮内上下文前后不一致；
2. readOnlyFiles 思想对应冻结面写保护，本项目已有更强的真源导出面静态扫描
   （`frozen-surface.ts:78-102`+测试），外显层人格/叙事文件可另建只读白名单机制，
   不与内核冻结面混用；
3. cron 部分只借任务状态机字段（C3）与 jitter/租约数据结构，明确不借 60 秒常驻 tick；
   文件租约选主要等多端同写场景（HLC 期）再评估，单机唤醒模型下任务表无需租约，
   避免把 Letta 的多实例复杂度提前引入。

#### (e) Cognee 双轨迁移账本 → 投影重建/迁移

【建议】新选择索引投影目录最小落地四件事（对照 Cognee slug/stamp/幂等链，调研报告
§3.7、§10.1-8）：

1. 投影元数据文件含 `schema_version` 与 append-only 的 `revisions.jsonl`（每条：slug、
   时间、输入真源指纹、行数/卡数对账摘要、触发原因），对应现有 checkpoint 的白盒 JSON
   风格，不引入 Alembic 类重型框架；
2. 重建/迁移启动先 stamp 当前真源指纹，顺序折叠后产出结构化对账报告（扩展现有
   `rebuild.ts` reconcile 报告，不另起体系），失败回滚到旧投影目录、损坏文件 rename
   隔离不删除（沿用 `detect.ts:172-184` 既有纪律）；
3. 全流程幂等：同真源+同 schema 重跑结果逐字一致，卡 id 与 edge id 一样由内容确定性
   派生（参照 D-9/D-11 的 edge id 决策）；
4. 模型/prompt 版本变更引发的重建走外审 C.2 纪律：先影子 diff 再切换，不作为日常操作。

#### (f) AstrBot/MaiBot 合成轮与概率门 → C 块预留影响

【建议】v1 不写 C 块代码，但选择索引与事件层设计需保证以下前提不被堵死：

1. 合成轮入口预留：未来 her 轮以 initiation='her' 的合成输入走同一管线（枚举已存在），
   内部调度信号（timeout、概率门分值、wait 计数）只允许进运行时状态/可重建投影，绝不
   进 experience/event 真源；主动轮真实发言仍按正常经历 append（主动说的话也是真实
   经历），与 MaiBot 插件伪触发不写消息库的边界区分清楚；
2. 概率门冷启动策略：无拟合数据前用保守静态阈值+全量观测埋点（呼应 D2 先观测），系数
   存配置/投影不进契约；上线后反馈调节只收紧不放宽（MaiBot 注释自证放宽会系统性话多），
   配空闲指数退避、静默时段、全局/会话暂停、日预算封顶；
3. 主动可观测：每次主动发言留触发原因/当时分值/回填的目标锚点日志（运行时态），给
   防打扰审计提供数据；平台主动能力 flag 默认关闭、校验真实支持（反 AstrBot 默认 true）；
4. 主动话题来源：由 reflection 叙事线与选择索引现场检索生成，不新建话题库、不新增真源
   字段，与 D3 叙事线定位衔接。

### 3.4 会诱导返工的风险点（显式清单，开工前逐条守门）

1. **把 selection/权重/线索字段顺手加进 event 投影**：E.5 已据此否决过替代架构——事件是
   二级真源、禁止算法高频重算，混入可变选择字段必然污染固化纪律。守门动作：评审时核对
   新投影 DDL 与 `src/projection/schema.ts` 物理隔离。
2. **锚点锚事件 UID 而非真源经历 id**：切分算法升级会重生事件 id（外审 B.1/D.3），第一天
   不锚 source_anchor 后期全量改锚。守门动作：代码评审禁止索引行出现无真源落点的长期指针。
3. **种子卡决策/漏召埋点格式不预对齐 D4 与 D.7**：P8 或删除闭包落地时台账成删除旁路、
   埋点成隐私旁路，需要数据迁移甚至销毁重采。守门动作：A4/A5 格式在首行代码前冻结。
4. **新投影无版本/对账字段**：重演现有 sqlite 投影 ADD COLUMN 打补丁路径（`sqlite.ts:133-142`）。
   守门动作：A3 四件套作为新投影 DoR（定义就绪条件）。
5. **P1 切分器接线缺陷未修即推进 C 块**：reopen/修正在主动轮场景频率上升后，事件层
   Unavailable 将从罕见手动路径变为常见事故。守门动作：C 块立项审批前把 §1.2 两条修复
   合并验收（含变异测试）；v1 离线第一步本身不被该缺陷阻塞，不得因此夹带修改。
6. **窗口装配期引入在线 LLM 重写/校验循环**：违反 E.4 与单轮一轮补取预算，且把延迟引入
   实时路径。守门动作：v1 所有校验只做离线审计，在线仅保留序号映射的确定性拒绝。
7. **以「业界标配」为由提前接向量/图库/常驻调度**：触发条件未到即施工，破坏零依赖与
   D5。守门动作：任何 kill list 项立项必须附 §2.2 对应触发条件的实测数据。
8. **半自动流程让 LLM 直接自由写 selection/权重且无决策留痕**：选择索引虽可重建，但无
   台账的 LLM 写入不可确定性重放（外审护栏 8 警示的最弱重建路径）。守门动作：所有 LLM
   产出经 A1 序号协议+A4 决策记录双闸门，重建=重放决策日志而非重跑漂移推理。
9. **prompt 改动不 bump 版本**：v1 若吸收 A6 取证条款却不升 SUMMARY_PROMPT_VERSION，
   溯源断链（v1.4 已有 v1→v2 先例，`implementation-notes.md` §10.2）。守门动作：prompt
   变更与版本号同提交、旧行版本号不回改。
