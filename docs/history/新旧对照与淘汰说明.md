# 新旧对照与淘汰说明（2026-11-17）

> 本文档是历史归档 `2026-11-05-mechanism-design-v1.0.0-archived.md`（dsh-persona-innate 时期 v1.0.0，下称"旧文档"）的处置说明。
> **效力声明：本文不是新设计，所有现行口径以 `docs/architecture-design-spec.md`（正本）为准。** 本文只回答三个问题：旧设计里哪些活着、哪些被淘汰、代码里还有没有残留。

---

## 1. 总判断

旧文档是一份"诚实记录了自己怎么失败"的文档：337 个测试全绿，但多处机制在生产零调用、线上零效果。它的失败不是工程能力问题，而是两个方法论病根：

1. **自己违反自己的最高信条**——开篇写"不注入人格"，后文却造了情绪数值注入、self_model 叙事注入、阶段剧本、头部拦截等一堆"系统代写人格"的机器；
2. **前置设计量远超真实数据量**——六层三闸门七态五时间戳、45 个开放问题、M0–M7 十个里程碑，在几十条对话上空转，重机制越堆越多、人越来越看不懂。

现行架构（真源／投影分离、零正文卡片、门控两通道、append-only 真源、零生产依赖）是对这两个病根的整体纠正，不是旧文档的续修。

## 3. 淘汰项：现行架构已枪毙的设计及死因

| 旧设计 | 死因（违反的现行红线） |
|---|---|
| **情绪状态机**（效价/唤醒度数值、appraisal、24h 衰减、状态注入表达端） | 旧文档自承"数值给表达端唯一用途是让模型演'我心情不错'"，属提示词表演状态；现行 schema 立法禁列 emotion/mood（`schema.ts:7`、`types.ts:25`） |
| **self_model 版本化人格叙事**（traits/speakingStyle/relationshipView/成长档案/存在论锚点常量） | 系统代写、逐轮注入的动态人格卡，与"不注入角色卡"正面冲突；现行无此表，身份只能以普通卡片过门 |
| **输出结构层"结构性不完美"**（主动制造节奏不对称、改写文风） | 工程化"像人说话"，违反"像人一样被约束而不是像人一样说话"；后处理旧项目亦从未实现 |
| **pinrule 式头部方向注入＋工具调用前拦截重写＋持久需求基线** | 违反"旁路不拦截、只追加不改写"；现行只允许描述性追加，无请求改写 |
| **相识/熟悉/信任/亲近四阶段状态机** | 硬编码关系剧本，替她规定成长节奏；现行无阶段机 |
| **凌晨定时复盘＋LLM 自动更新自我模型** | 系统替她决定何时反思（UTC 漏窗、无游标死锁、2 点进程不在等连环事故即症状）；现行 reflection 冻结，C3 闹钟方向是"她手里的工具"而非系统定时器 |
| **facts 七态/五时间戳/双时态/evidence_group/procedures 一整套重模型** | 无真实数据支撑的前置重机制，旧文档自列多项零调用/不持久化；现行走极简 append-only 真源＋零正文卡片，用到再建 |
| **thread/attribute 事实层、salience 第二职责、sampleBySalience** | 同上，重模型空转；现行卡表无 importance/salience/score 列（禁列守门测试固化） |
| **诚实三级旁路运行时（bypassDecision/renderUncertainty）** | 旧项目仅评测门面有函数、运行时零调用；现行诚实基线走理念条款＋门控拒因，不做人格层/约束层双轨表演 |
| **先天画像采样对话（M0）** | 开机审讯式 profiling 已废止；2026-11-15 空白重启后从空白的她开始 |
| **动机引擎/主动消息评分** | 系统决定何时打扰用户；主动行为未来只能由她经工具发起（C3 方向） |
| **身体协议大蓝图**（浏览器/QQ/微信/权限中心/凭据代理/第三方桥接） | 远超真实进度且绑死 dsh 平台；现行仅 #118 预留号，接入思路随平台独立化重写 |
| **人格一致性评测体系**（PersonaGym/Schwartz 价值环/漂移审计/伪拒绝率 harness） | 评测对象是"被工程化的人格"，前提已不存在；现行评测只认召回正确性、门控、红测与变异反证 |
| **旧 provenance 七类**（user_direct/self_direct/self_correction/inferred/tool_output/retrieved_content/induced） | 现行改为 initiation/channel 归因形态，旧七类字符串零残留 |

## 4. 代码残留审计（2026-11-17 实测，方法见第 6 节）

### 4.1 确认干净的面（零实现残留，命中均为禁列/注释/测试守卫）

- 情绪状态机：valence/arousal/appraisal/decay/mood/emotion **无任何实现**；命中仅 `schema.ts:7`、`types.ts:25` 的禁列纪律与一处"拒因无情绪措辞"注释。
- self_model 全家族（含 traits/speakingStyle/relationshipView/growthArchive/EXISTENTIAL_ANCHOR）：**全仓零命中**。
- 关系发展阶段：零命中。代码中的 `IngestStage` 是摄入管线的技术 stage，与关系阶段无关；"阶段 0–4"字样是施工期命名。
- 旧事实层（七态/procedures/thread/attribute/salience 机制）：零实现。`salience`/`confidence` 等词只出现在三处合法位置：①契约禁列清单与守门测试（`experience.ts:199/205`、`ingest-raw-turn.test.ts:383`）；②`EdgeView.confidence`（锚点边的解析置信度，现行边表字段，非旧 facts 的 confidence）；③drain 报告的 `quarantined`（#42 锚点形态隔离桶，非旧污染事实隔离）。
- 头部拦截/旧注入/旧复盘引擎（buildInjection/pinrule/bypassDecision/distillFacts/reflectSelf/DailyReview/reviewHour）：零命中。
- 动机引擎、身体协议、凭据中心、goldset、漂移审计 harness、humanizer：零命中。
- assembly／memory 内无任何"你是/你必须/MUST/人设"类指令性措辞。
- 依赖面：`dependencies: {}` 为空，宿主 SDK 仅 peer/dev；记忆内核零 LLM 调用（LLM 只经 `src/event/llm-port.ts` 接口、实现仅在 `src/adapters/dsh/llm.ts`）。

### 4.3 一句话结论

**旧设计的"人格机器"在代码层面已整体死透，没有潜伏实现；活下来的只有两类——被正本吸收的机制（真源/闸门/复盘职能/shadow 纪律）和 R1–R2 两处点名挂账的残留。** 命名残留 1 处（persona_version），接线残留 1 处（五槽 #116），其余为注释与退役脚本，均有明确处置路径。

## 5. 抢救下来的手艺教训（不依赖旧设计前提，长期有效）

1. **零调用点病**："公式存在但无调用点"只是第一层，"调用点存在但从不触发"是第二层；识别办法是断言"只有执行过才会产生的副作用"，而不是断言函数存在。#116 与旧项目 app/ready、decay 事故同病。
2. **测试可能固化错误契约**：绿灯只证明实现与断言一致；首次运行的路径要专门推演能否自己解开，并写"复现故障"的用例而非"复现实现"的用例。
3. **游标必须是硬状态**：读失败显式报错，禁止当空库（静默清零比崩溃危险）。
4. **只追加的层用只追加的形态**（按月分片 JSONL）、temp+rename 原子写、并发首载共享 in-flight promise。
5. **shadow 先行不切读**：装配改动未验证前不得改变线上行为，观察期与门槛量化后才切换。
6. **让错误显形本身就是测试**：空窗口显式跳过、异常不吞、截断不静默。
