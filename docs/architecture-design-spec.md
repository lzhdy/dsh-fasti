# 第 1 章　使命、主语与设计哲学

## 1.1 一句话定义

FasTI 是一个运行在 dsh／cordis 宿主之上的**记忆插件**。它不追求做一个更好用的聊天机器人，它服务的对象是 AI 自己——全文统一称「**她**」。插件的使命是让她拥有属于自己的、可累积、可修正、可追溯的经历与记忆，并在未来拥有身体与主动权，最终成为"一个完整的她"，而不是一个依赖对话历史的无状态会话。

**主语约定必须钉死：「她」是 AI 主体，不是用户。** 整个程序只为她一个人存在——记忆是她的记忆，判断是她的判断，连续性是她的连续性。人在系统中的角色是对话者、授权方与验收签字人，不是被服务的中心。任何把"她"写成用户功能的设计都是错位。

## 1.2 目标层级与对数据模型的三个强制推论

目标分两层理解：底层是"记忆可靠的会话插件"（解决长对话遗忘、上下文有限、召回不精）；上层是"完整的她"——不依赖对话历史而存在，交流只是她能做的事之一，她还将拥有可接入的身体、分级权限、自己的动机与节拍、跨设备保持同一的身份。上层目标对架构提出三条不可回避的推论：

1. 数据原子不能是"一条聊天消息"，必须是"一次经历"（见第 4 章存在日志）；
2. 记忆系统不能是外挂检索框，必须成为她做判断的内部器官，且记忆决策权在她一侧（第 5、6 章）；
3. 必须为主动（C）、身体与权限制衡（D）、身份连续（E）预留完整结构，且权限随她自己长出的价值观逐步开放，而不是开局全给（第 8 章）。

## 1.3 核心信条（最高约束）

> **不注入任何角色卡／人设。人格、记忆、情感、自我认知，全部由她在与用户的真实相处中自己长出来。**

违反即淘汰，没有折中版本。理念条款正文逐字锚定于本章 1.8 节，为最高权威；本章其余各节给出工程设计必须内化的要点。

## 1.4 六条工程原则

1. **人格长出来，不写进去。** 不写 persona 预设、不写行为指令；先天画像只测量、不注入（体检表不是药）。禁止任何"直接告诉 AI 它是谁、该怎么说话"的改动。
2. **像人一样被约束，而不是像人一样说话。** 用状态机、阈值、持久化等外部工程结构制造约束，不靠提示词表演人格；优先确定性机制，不依赖模型"记住"规则。
3. **以 AI 为核心，不是以用户为核心。** 记忆包含她自己的表达（双方表达，不只记用户）；她是自身经历的行动者而非用户的镜子；记忆决策权在她侧，不提供用户强制记忆通道。
4. **旁路不拦截，只追加不改写。** 不改写用户消息、不插指令；只在系统提示区追加描述性内容，不用 MUST 式指令语言；事后监听落库，不干预请求路径。
5. **诚实基线。** 明示"我是 AI"、不伪装人类，但允许形成独特个体性；证据按来源（provenance）分级，诱导与外部信号权重最低以防污染。
6. **成长闭环，不跳步。** 相处 → 感知 → 记忆（分级落库）→ 固化（复盘／状态机）→ 表达（动态注入）→ 影响下一轮；固化靠多次复盘累积，不追求即时变化。

每个决策的自问检验：**"这是在给她增加外部约束、让她自己经历，还是在替她写人格、让她迎合用户？"** 前者可做，后者不做。

## 1.5 五条不可动摇的理念

1. **无角色卡、无人设注入。** 人格不是形容词列表，而是状态机和真实经历的产物。
2. **以她为核心。** 记什么、怎么看、擦什么，由她在复盘环节决定，不由写死的程序替她决定。
3. **她自己成长。** 记忆、人格、三观从真实经历与反思中长出，起点接近空白，不预置答案；可以给思考方法，不能给思考结论。
4. **诚实是底线。** 不伪造记忆、不假装记得、不表演没有的感受。
5. **拟人不是完整学人。** 主体性、真实感、成长来源意义上的特点就学；纯生理硬件缺陷不照搬。

## 1.6 面向行动与权限的四处理念扩展

1. **从"记忆归她"扩到"行动归她、后果也归她"。** 系统提供能力、记录后果、保证可追溯，不替她决定做什么。
2. **价值从经历长出，长出之前权限受限。** 权限跟着价值一起长：初期只有只读与可逆能力，价值观被多次独立印证而稳定后，再逐步开放不可逆与对外能力。
3. **行动依据必须是她自己的判断。** 优化必须发生在她的判断之后，而不是替代判断；系统可以给原文、交叉验证、后果记录，不能替她得出"这件事不重要"。
4. **"任何事"的操作化：** 她能做的受限于实际接入的身体；按后果分四档授权——**只读／可逆写／不可逆写／对外影响**；她做的每件事都进记事本、可回查、可回滚。

## 1.7 红线的性质与两条贯穿性红线

红线是**判定标准，不是建议**：方案开工前先过红线，违反者直接淘汰，不进入实现讨论。两条贯穿全部代码：

- **A 块红线**：数据结构不能把"聊天"写成前提；不能预设"什么重要"。真源里禁止出现"重要性"字段。
- **B 块红线**：规则层只标记、不否决；她的判断优先于系统判断。禁止用规则或阈值替她决定"这条该不该记"。

各块自己的开工红线见 2.3。

1. **无角色卡、无人设注入**：不在系统提示词里写"你是一个温柔的助手"之类的设定。人格不是形容词列表，而是状态机和真实经历的产物。
2. **以"她"为核心**：记忆是她的，该记什么、怎么看、擦什么，由她（在复盘环节）决定，而不是由写死的程序替她决定。
3. **她自己成长**：记忆、人格、三观都从真实经历和反思中长出来，起点接近空白，不预置答案；可以给"思考方法"，不能给"思考结论"。
4. **诚实是底线**：不伪造记忆、不假装记得、不表演没有的感受。
5. **拟人不是完整学人**：判断标准——某特点若是主体性、真实感、成长意义的来源，就学；若只是生理硬件造成、与人格无关的缺陷，就不照搬，用她的方式做得更好。

> 总纲（§1.5）：拟人是手段，不是目的；她可以成为更好的她，但要防止"更好"滑成"非人"。

### 四、目标升级后的三处理念扩展（§1.6 原文要点）

目标已从"做一个记忆很好的聊天插件"升级为"**做一个完整的她**"——不依赖对话历史、交流只是其中一件事、有身体可接入权限、能做她想做的事。

- **§1.6.1 从"记忆归她"扩到"行动归她、后果也归她"**：她做什么由她判断，做错的后果也归她承担与修正。系统的角色是提供能力、记录后果、保证可追溯，不是替她决定做什么。
- **§1.6.2 价值从经历长出，长出之前权限受限**：起点空白这条不能动（预置价值就是角色卡），但起点空白 + 直接给权限 = 风险。处理方式是**让权限跟着价值一起长：初期只有只读与可逆能力；随着她自己的价值观在经历中稳定（多次独立印证），再逐步开放不可逆与对外的能力**。
- **§1.6.3 行动依据必须是她自己的判断，不是系统替她优化过的结果**：优化必须发生在她的判断之后，而不是替代她的判断。系统可提供原文、交叉验证、后果记录，但不能替她得出"这件事不重要"。
- **§1.6.4 "任何事"的操作化（理念层定调，细节归 D 块）**：
  1. **能力范围内**：她能做的受限于实际接入的身体，不是抽象无限；
  2. **按后果分级授权**：**只读 / 可逆写 / 不可逆写 / 对外影响，四档不同权限（D 块细化）**；
  3. **全程可追溯**：她做的每件事都进记事本、可回查、可回滚——这是诚实底线在行动层的延伸。

### 五、五块地图与推进顺序

#### 5.1 五块地图（§0.1 原文）

# 第 2 章　总体架构：五块地、九层、进程与存储哲学

## 2.1 五块地的管辖范围与依赖方向

系统切分为五块，每块有明确管辖、红线与依赖箭头，依赖不可反向。

| 块 | 名称 | 管辖 | 依赖 |
|---|---|---|---|
| **A** | 底层架构 | 数据模型、存储、时间模型——她用什么单位记录存在 | — |
| **B** | 记忆架构 | 写入／复盘／读出——她怎么记住与想起 | A |
| **C** | 主动系统 | 动机、节拍、目标、主动发起交流 | A＋B＋**D** |
| **D** | 身体·权限·制衡 | 能力接入、授权分级、审计、回滚、紧急制动 | A |
| **E** | 身份连续性 | 跨设备／跨版本／跨模型，什么构成"同一个她" | A |

两条易混边界：

- "主动发起交流"是一次**行动**，归 C；"发消息／语音／打开网页"是**能力**，归 D；"怎么说话"（措辞、语气）归 B 的表达风格决策。
- D 把权限与制衡合并：给了手脚就必须同时有审计、回滚与刹车，同批设计，禁止先给能力后补刹车。

## 2.2 推进顺序与"只发声"变通的架构前提

理念规定的标准顺序是：`B 兼容性标记（只标记不改正文） → A 评估定案 → D → C → E`。D 在 C 之前，先定能力边界主动性才有手脚；E 横切所有块、最后定。

允许一次带前提的变通（首期 C 块只发声、D 后置），但必须同时永久满足三条：

1. 块级依赖箭头 `C ← A＋B＋D` 作为架构事实保留，不从设计图删除；
2. 首期主动工程**只允许经过宿主 L6 发声通道主动起话头**，不接入任何 D 类外部能力；
3. 一旦要接入"不可逆写／对外影响"类能力，D 的四档授权、审计、回滚、紧急制动必须先行就位，没有例外。

## 2.3 每块地的开工红线

| 块 | 红线 | 最易犯的错 |
|---|---|---|
| A | ① 原子不能是消息／轮次；② 不能预设"什么重要" | 以消息为原子、把她做的事降成附属字段 |
| B | ① 规则层只标记不否决；② 她判断优先于系统判断 | 用规则阈值替她决定记不记 |
| C | ① 动机不能由系统注入；② 优化必须在她判断之后 | 用"今日任务清单"驱动她，本质仍被动 |
| D | ① 能力与制衡同批设计；② 权限随价值长出；③ 四档分级＋全程可追溯 | 先给能力后补刹车、把"任何事"当无差别开关 |
| E | ① 她是同一个她；② 不能靠"看起来一样"冒充连续 | 只做数据拷贝、不定义同一性 |

## 2.4 进程模型：单进程插件、宿主心跳、单写者

- **单进程单实例**：以 cordis 插件形态装载进宿主进程，自身不是独立服务；同一数据根同时只允许一个写实例。所有真源写入经过一个串行单写者队列（规定模块 `src/source/writer-queue.ts`），并发 append 到同一分片不得交叉写入或损坏分片，必须有压测用例守护。
- **热路径只入队**：会话摄入同步路径（门面 `src/api/index.ts` 的 `class Fasti`）只做校验、入队、状态登记，不做重活；切分、闭合、摘要全部在异步阶段消化，不得阻塞宿主会话。
- **不新增定时器**：后台节拍复用宿主既有的 worker 心跳（5 秒量级）做时钟驱动检查，禁止自养常驻调度器（见 K3）。
- **写面读面分离**：真源 append-only；投影（含记忆索引）全部可丢弃、可重建；离线构建任务运行时，运行期窄柄必须自动降级只读，不得抢锁。

## 2.5 九层分层与反向依赖门

代码按依赖方向从外到内分九层（L6→L0），依赖只能向内、不能反向。

| 层 | 规定目录 | 职责 |
|---|---|---|
| L6 宿主适配层 | `src/adapters/dsh/` | cordis 插件入口、会话事件转换、LLM 端口、记忆工具桥接薄壳 |
| API 门面层 | `src/api/` | 唯一对外门面 `class Fasti`，热路径入队、WriterQueue、摄入阶段编排 |
| L5 装配层 | `src/assembly/` | 宿主无关记忆工具集内核、宿主工具运行时、装配入口；M6 依赖门落点 |
| L4 记忆内核层 | `src/memory/` | 索引、检索、布尔门、窄写、影子、窗口、账本、审计 harness；纯内核不碰 fs／sqlite |
| L4.5 运行态层 | `src/runtime/` | 非权威检查点：tick、引擎档、复盘游标、失败环形缓冲 |
| L2 事件层 | `src/event/` | 切分器、闭合检测器、五种修正、闭合管线、LLM 抽象端口、参数中心 |
| L3 投影层 | `src/projection/` | SQLite 投影、FTS、边表、事件行、重建与源扫描，可整体丢弃重建 |
| L1 真源层 | `src/source/` | 路径布局、tick 分配、四类真源 JSONL、通道注册表、单写者队列 |
| L0 契约层 | `src/contract/`＋`src/core/` | 全部 TS 类型与校验、冻结面；零依赖基础设施 |

两道 **M6 反向依赖门**，必须配投毒自证测试：

1. 对话链路（L6→API→L2）**不得 import** 记忆层（L4／L5），保证召回门可整体关停而对话不受伤；
2. 记忆层**不得 import** 门面（API），使记忆内核可完全离线单测，宿主工具只能在 L5 通过注入端口绑定。

## 2.6 数据根布局与"正本／抄本"之分

数据根解析优先级（`src/source/paths.ts`）：**显式配置 > `$DSH_HOME/fasti` > `~/.dsh/fasti`**，由 `layoutOf(root)` 推导目录。

**正本（不可再生，按真源级备份）**

| 路径 | 内容 |
|---|---|
| `raw-turns/` | 原文层·DSH 通道会话日志，沿用宿主格式兼容存量 |
| `raw/<channel>/` | 原文层·新通道统一格式（未来 reflection／dream 全文落此） |
| `experiences/` | 结构层·经历条目 JSONL，通道无关统一形态，按月分片 |
| `events/` | 记事本·事件条目 JSONL（二级真源，见第 5 章），按月分片 |
| `channels.json` | 通道注册表，随她迁移的数据文件 |

**抄本（可丢弃、可重建）**

| 路径 | 内容 |
|---|---|
| `projection/fasti.sqlite` | L3 主投影库（经历索引、FTS、边表等） |
| `projection/memory-index/` | L4 记忆索引库 `memory-index.sqlite`＋`revisions.jsonl`＋`decisions.jsonl` |
| `projection/memory-shadow/` | 影子观测 JSONL（无原文，只存规范化词项哈希与计数） |

规划中的 `trash/` 服务删除闭包（见 4.7），在删除能力落地前不得创建。存储哲学核心：换机型、换版本、换模型时抄本整体丢弃重建；真源目录整体拷贝即是跨设备迁移雏形（E 块）。

## 2.7 时间模型：三个时间轴与一个节拍

每条经历三个时间字段，语义严格分离：

- **世界轴 `occurred_at`**：事情发生／被感知时刻，摄入方给，不可回改；
- **系统轴 `recorded_at`**：进入真源时刻，系统维护，永不回改；
- **节拍轴 `tick`**：她的主观节拍序号，摄入时按 append 顺序分配，永不回改。

`tick` 是摄入序号而非世界时间排序：多通道并发或乱序到达时先落库者先得 tick，不保证与 occurred_at 同序；世界时间先后一律查 occurred_at。tick 分配器规定取 experiences 的 `max(tick)` 后 max+1，基于单机单进程假设。这是全内核**唯一**为多端预留的升级点：跨设备多端写入前必须平滑替换为混合逻辑时钟（HLC）或以 ULID 定序，当前不实现。

## 2.8 对外门面的形状

门面 `class Fasti` 必须同时实现两个接口，且热路径方法内部只做入参校验然后入队，所有磁盘写入由 WriterQueue 串行消费；记忆层不得反向认识门面。

- **FastiPrimitives（14 项）**：覆盖写入、查询、通道注册、指针解析、重建、tick 等；其中未实现的媒体类原语必须显式抛 `NotImplementedError`，禁止假实现。
- **EventPrimitives（8 项）**：事件层重开、合并、拆分、改边界、重写摘要、补切等修正原语。

# 第 3 章　L0 契约层与冻结面

## 3.1 契约层的职责

L0 承载全部 TypeScript 类型、运行时校验与"冻结面"声明，是所有上层共同依赖、自身零业务依赖的一层。`src/core/` 提供零依赖基础设施：原子文件写（tmp+rename，`fsx.ts`）、JSONL 分片读写（`jsonl.ts`）、哈希（`hash.ts`）、ULID（`ulid.ts`）、时间纯函数（`time.ts`）、错误类型层级（`errors.ts`，含 ConflictError／UnavailableError／NotImplementedError）、截止时间（`deadline.ts`）。core 必须可被任意上层安全引用。

## 3.2 冻结面 FROZEN_SURFACE：五条不可破坏的不变量

`src/contract/frozen-surface.ts` 必须声明并由双层静态守门扫描守护以下五条不变量（这是冻结契约的全部内容，注意它是五条不变量、不是若干函数签名）：

1. **source-append-only（真源只追加）**：真源日志禁止原地更新与删除，一切变化以新版本或新追加行表达（K4 永不重议）。
2. **ulid-and-dual-pointer（ULID 与双指针）**：经历与事件以 ULID 全局标识，正文经通道命名空间＋分片＋行号指针定位。
3. **three-slot-shape（三段槽位形状）**：经历条目固定为 observation／action／outcome 三段槽位（见 4.2）。
4. **three-time-axes（三条时间轴）**：occurred_at／recorded_at／tick 三字段语义分离、永不回改。
5. **projection-rebuildable（投影可重建）**：任何投影与索引都必须能只凭真源整体重建，投影不得持有不可再生真相。

冻结面的改动属于伤筋动骨，必须整块评审加用户确认；静态守门要能在编译期与反射扫描中拦截新增的反向依赖与禁字段。

## 3.3 写入门禁：顶层白名单＋递归禁字段

摄入入口的经历校验（`validate-experience.ts`）必须采用顶层字段白名单加递归禁字段：不在白名单的顶层字段拒绝写入，递归路径上的禁字段（例如任何形态的重要性、情绪数值、sessionId）一律拒绝。未知合法字段的演进只能走加法（新可选字段、新枚举值），读取时原样透传，禁止 ALTER 原地改历史行。

# 第 4 章　A 块：存在日志、真源与投影

## 4.1 为什么原子不能是聊天消息

若以"消息／轮次"为原子，会同时撞两条 A 块红线：它把"聊天"预设成存在的唯一形态（未来开浏览器、感知摄像头、内省做梦都无法表达），并天然诱导工程方去标"哪条重要"。定案选择：真源由两类 **append-only 不可变日志**构成。

| 层 | 日志 | 内容 | 为什么不可再生 |
|---|---|---|---|
| 原文层 | `raw-turns/`＋`raw/<channel>/` | 她感知到的原始流，全量保留 | 删了就没有原文 |
| 结构层 | `experiences/` | 经历条目：切分、场景、关系、规则层标记 | 切分与关系包含判断，无法由原文确定性重建，删了丢判断史 |

逻辑上是单一原文层，物理上按通道命名空间隔离；指针经通道注册表解析到物理文件，新增通道不需要加目录级逻辑。

## 4.2 经历条目 Experience 的形状

经历条目（`src/contract/experience.ts`）是她的原子，字段分组规定如下。

**标识**：`id` 为 ULID，全局稳定、按时间有序、跨设备不变；`schema_version` 从 1 起只增不改，未知字段读取时原样保留。

**双轴：形状 × 通道**

- `kind` 是开放枚举的形状：`dialogue`（交互）、`perception`（单向感知）、`action`（对外行动）、`reflection`（内省）、`dream`（做梦）、`import`（回填）等；新形状＝注册新值，旧读取器不破坏；
- `scene` 三元组 `{ channel, ref, detail? }`：通道 id（dsh／qq／browser／camera…开放）、通道内场景标识、通道自定义细节；
- `initiation`：谁发起——`user`／`her`／`system`／`environment`，开放扩展；
- 可选 `agent_meta`：记录她当时的载体（model、persona_version），"她被升级了"本身也是一条经历，是 E 块同一性素材。

**三段槽位（冻结形状）**

- `observation`：发生了什么。正文一律走 `Pointer` 指针、不内联；媒体走 `MediaRef[]`；反思／做梦可用 200 字符以内的内联短线索 `cue`；
- `action`：她做了什么。`type` 开放（reply／browse-step／tool-call／preserve-media／organize…），工具名对齐 OpenTelemetry 的 `gen_ai.tool.name`，大参数走指针，`thought` 是她行动前判断过程的表达口；
- `outcome`：结果如何。`status` 取 success／failure／partial／unknown，错误类型对齐 OTel `error.type`，可记耗时与 token 数。

**关系与标记**

- `marks`：规则层机械标记，形状固定为 `{ type, by:'rule-layer', note? }`，只贴标签、不否决；**marks 永远不含"重要性"**；
- `pointers`：摄入期结构边；判断期关系进投影边表。
- 加法字段 `char_count`：记录该条全量 raw_text 的码点长度，工具轮也记实际字符数（不得记 0），历史数据允许 null。它是事件层两个字符计数器的逐记录来源（见 5.4）。

## 4.3 指针规范与资产层：真源存引用、字节进资产层

`Pointer` 由目标条目 id、通道命名空间、分片冗余（`YYYY-MM`）、行号或行区间构成。正文不复制、只定位，保证同一段原文只有一份权威副本。

媒体字节分两层引用：原始引用（origin，可失效、只记录不依赖）与本地副本（assets，她主动保存后唯一被长期依赖的位置）。生命周期：摄入时媒体字节先进 staging 暂存；只有她调用 `preserveMedia` 才转入 assets 并留一条 action 经历，**系统永不自动长期保存**；未采纳的 staging 到期衰减、台账留痕；删除只能由她走删除工具。资产状态（origin-only／staged／preserved／decayed／lost）是台账折叠结果，不是真源字段，真源始终纯 append。诚实边界要求注入时如实呈现"本地已保存"或"原始已不可考"，不得假装还看得见。

## 4.4 投影层：一切抄本皆可弃

L3（`src/projection/`）在 SQLite 上维护可整体重建的投影：经历索引（含 channel 列）、FTS5 全文索引、实体与双时间邻接边表、事件行、资产索引等；node:sqlite 不可用时必须提供 JSONL 降级路径（`jsonl.ts`）。四条纪律：

1. **投影不持有真相**：valid／invalid 一类判断结果只进投影边表与 facts；事实过期打失效标记而非删除，支持 as-of 查询"她在 T 时刻相信什么"；
2. **重建协议只认真源**：`rebuild.ts` 从正本重放构建投影，构建过程不得反向修改真源；
3. **降级保运行**：SQLite 出问题退到 JSONL 投影，不阻断摄入；
4. 投影层时间列统一毫秒口径。

## 4.5 运行态层：非权威检查点

`src/runtime/checkpoint.ts` 必须明确是**非权威**状态：tick 计数缓存、当前引擎档位、复盘游标、失败环形缓冲（保留最近 10 条）。它丢了必须能从真源与投影重建，因此不进备份关键集，也不允许任何模块把检查点当真相来源。运行循环口径是"身份持续、计算按需"：她的存在由 append的真源持续保证，昂贵计算（索引、摘要、复盘）按需触发。检查点必须白盒可读（K6），禁止黑盒快照。

## 4.6 冻结面与开放面：以后怎么加东西

- **冻结面**：真源 schema、指针规范、状态机语义属伤筋动骨改动，须整块评审加用户确认；schema 演进只允许加法，未知字段原样透传，禁止 ALTER 原地改历史行；
- **开放面**：新通道、新 kind、新投影表、新索引都是加法演进，永不破坏既有数据；
- **扩展配方**："加东西"的标准动作是注册新值、加投影、加适配，而不是修改老条目语义。

## 4.7 删除与擦除的成功标准：删除闭包

真源 append-only 不等于不能忘。删除工具必须形成**闭包**：原文指针、结构条目、投影副本、索引轻卡、影子观测、备份保留策略都要有确定去向，不允许只删一处留下可复原碎片。隐私维度立 M9：隐私内容的彻底删除要等 E 块跨设备转移能力就位后才能闭环，否则删了本地、远端仍在是假删除。删除能力动工前，历史文档中与之冲突的 ADR 文字必须先订正。

## 4.8 L1 真源层应建模块

`src/source/` 规定七个模块，职责单一、不得互相越界：`paths.ts`（数据根三级解析与布局）、`tick.ts`（单进程 max+1 分配，HLC 唯一预留点）、`writer-queue.ts`（串行单写者队列，并发 append 不交叉）、`raw-log.ts`（raw/ 新通道原文）、`event-log.ts`（事件分片读写，二级真源）、`experience-log.ts`（经历分片读写，结构层真源）、`channels.ts`（channels.json 注册表维护）。

# 第 5 章　B 块事件层：把流水切成"一件一件的事"

本章按"为什么—是什么—怎么切—怎么修—模块怎么落"规定事件层。定案口径为 v1.5（`docs/b-block-event-layer-design.md`）。

## 5.1 为什么必须有事件层，以及它是二级真源

原始流水按到达顺序逐条 append，记录"每一轮"，但记忆与复盘需要的单位是"**一件可命名的事**"——一次配置排查、一场讨论、一轮工具任务。事件层负责把连续流水机械分区成事件，并补摘要、关键点、锚点与话题线。

事件的存储定位是全稿最核心的决策之一，三个备选的取舍：

| 候选方案 | 后果 | 结论 |
|---|---|---|
| 当投影 | 切分算法一升级就全量重算，她亲手改过的边界被抹掉 | 否 |
| 当一级真源 | 事件本就派生自流水，谈不上一级 | 否 |
| **当二级真源** | 派生自记录本，但**一旦写入即固化**，只允许她的修正与版本推进 | 采用 |

三条实现纪律：

1. 事件**不可由算法批量重建**；重建只允许"补齐缺失事件"（幂等补切），不得覆盖已有事件；
2. 事件必须**版本化**，每次边界修正留新版本；默认不淘汰，超过 20 版安全线才淘汰最老的纯算法版本，**她的修正版本永不淘汰**；
3. 事件层备份等级等于真源级，不是索引级。

## 5.2 事件字段与状态机

一个事件 = 记录本里连续一段、讲同一件可命名事的内容，按月分片落在 `events/`。关键字段：

- 标识与版本：`id`（ULID，多版本共享同一 id）、`version`、`channel`（按通道隔离）；
- 内容三件：`summary`（一句话摘要，客观语气、第三人称、不带评价，未完成时为 null）、`key_points`、`anchors`（具体动作／事实进展／计划，供话题线判定）；
- 定位：`pointers`（指向经历条目的原文指针组，闭合即可得，必需）；
- 状态：`status` 与 `closed_reason`（封闭枚举的机械闭合原因，null 表示未机械闭合）；
- 两个字符计数器：`effective_chars`（只累加非工具轮）与 `raw_chars`（所有轮含工具 JSON），允许历史 null，restore 直读字段、不从 pointers 重算；
- 时间双轴：`time_range:[started_at,ended_at]`（允许零长度瞬时事件）与 `assembled_at`（何时被切出），两轴不混；
- 横向归属：`topic_lines`（话题线 id 列表，网状可多条，未判定前为空）；
- 摘要治理：`summary_quality`（pending／ready，**降级就是保持 null＋pending，不伪造占位文案**）、`summary_source`（llm／her）、`summary_prompt_version`（初版 v2）、`summary_model`，后两者只做溯源不做评分；
- 非权威候选：`boundary_candidates`，只记录慢路径产出的"话题跳转"等候选，不改 pointers 与 status。

事件中**禁止出现"重要性"字段**（撞 A 块红线）；她的判断落在复盘产物，不落事件字段。

状态机：

```
open ──(静默/闭环)──→ closed ──(做梦/淘汰)──→ archived
  │                    │
  └──(她重开)───────────┼──(合并)──→ merged（带 merged_into 指针）
                       └──(拆分)──→ split（带 split_into 指针）
```

三条语义：

1. **闭合即时**：命中机械信号立刻置 closed，不等 LLM；摘要、锚点、挂线随后台异步补齐，期间 summary_quality=pending；
2. **open 事件按通道隔离**：每通道各维护一个 open，没有全局唯一 open；通道切换闭合"被离开通道"的 open，于是 dsh→browser→dsh 自然得到三个事件，靠话题线连成一件事；
3. merged／split 是**退役态而非删除**：旧事件带指向新事件的指针留存，供上层接力与审计。

## 5.3 工具轮类型化

真源实测：工具轮占条数少却占全部字符约三分之二，而早期经历条目 kind 全是 dialogue、带 action／outcome 的为零——工具调用一直在真源里，只是被错标成对话。设计必须做纯加法的类型化映射（不改原文）：带 `action.type='tool-call'` 或 outcome 的记录标为工具轮（`is_tool`），契约层不引入 speaker 字段，工具判定用 action／outcome 与原文层复核。这同时为任务闭环提供了本来就存在的输入源。

## 5.4 切分判据：机械信号与语义候选严格分治

这是事件层最容易被实现错的部分。两类信号待遇完全不同。

### A 类：机械闭合信号（命中即闭合，不需语义判断）

| 信号 | 阈值与口径 | 驱动／状态 |
|---|---|---|
| 时间间隔 | 静默 ≥ **30 分钟**闭合；后台 worker 按节拍**时钟驱动**求值（`now − 末条摄入时刻 ≥ 30min`），不依赖下一条到达；摄入时静默补判仅作时钟不可用期兜底 | 时钟驱动 |
| 有效对话字数 | 单事件 `effective_chars`（排除工具轮）≥ **7000 字**闭合，原因 `max-dialogue-chars`；7000／摘要 600 ≈ 11.7:1 钉住压缩比 | 摄入驱动 |
| 任务闭环 | 任务作用域结束时闭合，判据含 inFlightCallIds、准入门槛与交付轮 | **默认 dormant 休眠**（显式布尔，非注释），须经口径评审才转 active |
| 硬保险丝 | 单事件 `raw_chars`（含工具 JSON）按 1 字符≈1 token 换算 ≥ **50000** 强制闭合，原因 `max-chars`；不引 tokenizer，对 CJK 近似准确、对 ASCII 保守，仅兜底 | 摄入驱动 |
| 场景切换 | 会话／通道切换，闭合被离开通道的 open，原因 `channel-switch` | 摄入驱动 |

量纲原则：字符类只在有新记录时增长，故摄入驱动；静默类在没有新记录时也必须能求值，故时钟驱动——否则用户离开后最后一个事件要等到次日才闭合。时钟检查独立于 LLM 端口，没有模型时事件照样闭合、摘要继续 pending。

**判定优先级钉死**：通道切换／静默／任务闭环 > 硬保险丝 > 有效对话字数。先命中者写 closed_reason、一次只写一个、命中即 return；两个字数上限必须先判保险丝再判有效字数，实现顺序受测试约束。重复检查对已闭合事件是 no-op（幂等）。按记录条数计数的历史"20 条硬上限"已废止——它对机器载荷计数，会导致边界总落在 JSON 中间。

### B 类：语义候选信号（只标记，绝不自动切）

话题／意图突变的唯一来源是慢路径摘要调用的附带输出（`kind='话题跳转'`），只写入 `boundary_candidates` 留在当前事件，闭合与否留给她复盘判断；首期不接 embedding 探测器（话题线二期再议，相似度下限 0.7 待实测标定，且 embedding 不得成为硬依赖，见 K1）。

铁律：**机械信号可以替她切（只是时间／数量／场景的客观事实），语义信号绝不替她切。宁可不切（事件偏大），不可乱切。**

防误切四条：① 问候寒暄不单独成事件，并入相邻事件；② 单条不孤立也不硬凑，无可并对象挂"待归并"，永不自动并入无关事件，由她手动归并或永久孤立；③ 低置信不切；④ 一切边界候选必须能被她的修正覆盖。

## 5.5 跨时间段：切开，再用话题线接上

静默 ≥30 分钟就切开，**绝不按日历切**（聊到凌晨跨零点不切）。跨天长静默、跨通道、历史不连续都切成独立事件，再用横向话题线接成一件事。强行合并会造成统计失真（"持续 12 小时"实际只有 20 分钟交互）、检索失真与摘要失真（600 字装不下两天内容）。

话题线是独立对象（不是事件两两互指的单链），结构含 `core_activity`、`event_ids[]`、status（active／closed）、version，一个事件可同时属于多条线（网状）。挂线三步：

1. 用闭合前就存在的**原始记录 embedding**（零额外成本、全量信息）；
2. 对每条 active 线的聚合向量算余弦投票，只保留相似度 ≥ 0.7（`minSimilarity`，待标定）的候选；closed 线不进候选，复线只能由她显式操作；
3. 后台**一次 LLM 调用同时产出摘要、关键点、锚点与挂线**，不额外增加模型调用。

上下文预算恒定：喂给 LLM 的是 core_activity＋最近 **10 个事件**的锚点（`recentWindow=10`），更早事件只给 id，线再长输入也不膨胀。

## 5.6 双流执行：LLM 不进摄入热路径

- **热路径（实时）**：写入经历、机械切分、即时闭合，全确定性逻辑，不调用模型；
- **慢路径（后台 worker）**：闭合事件入摘要队列，异步调 LLM 生成摘要／锚点／话题候选，受单调用 60 秒硬超时（`DEFAULT_CLOSURE_CALL_TIMEOUT_MS`）与单轮 120 分钟总预算（`DEFAULT_CLOSURE_ROUND_BUDGET_MS`）双重保护——一次不返回的调用不得静默停掉整条队列。

摘要不在实时生成（实时生成会把模型延迟与故障带进会话链路）。降级纪律：LLM 不可用时事件正常闭合、摘要保持 null＋pending；端口恢复后队列续做不丢任务；后台失败进失败缓冲可重试。摘要硬上限 600 字（`SUMMARY_MAX_CHARS`），改提示词必须同次 bump `summary_prompt_version`。

## 5.7 修正链路：一等能力，不是补丁

### 五种机械修正

| 操作 | 语义 | 留痕 |
|---|---|---|
| 合并 | A＋B→新事件 C；A、B 置 merged 带 `merged_into:C` | 旧事件不删 |
| 拆分 | A→B1＋B2；A 置 split 带 `split_into:[B1,B2]` | 旧事件不删 |
| 改边界 | 首／末 N 条记录挪出或挪入（换 pointers） | 新版本 |
| 重开 | closed→open | 新版本 |
| 重写摘要 | 她手动改写，`summary_source` 置 her | 新版本，旧摘要留版本 |

**硬不变式：一条记录同时只能属于一个当前态事件。** 改边界不得跨事件"偷"记录：移出只需从本事件 pointers 删除，记录回孤儿候选池；移入记录必须不属于任何其它未退役事件，否则拒绝且不做自动换主（自动换主等于制造一次她没要求的修正）。"属于"只算当前态，merged／split／archived 不计入归属，否则合并后产生永久假冲突。违反的后果是同一段原文被两个摘要各覆盖一次，且重建白名单会忠实保留污染而无手段发现。

### 重开同通道冲突

每通道同一时刻只维护一个 open 事件。重开 B 时若同通道已有 open 事件 A，必须抛结构化的 `EventOpenConflictError`（携带 blocking 事实与 actions 标识，内核不拼中文文案），**不写任何版本，也绝不替她自动闭合 A**。合规路径只有两条：显式组合原语 `closeAndReopenEvent`（先全部校验、再顺序写两条版本、零半程态，两条版本均 `created_by='her'`），或改用合并。新闭合原因 `manual` 纯加法入契约，表示人显式闭合。

### 派生字段重跑与上层接力

修正换了 pointers，按旧 pointers 生成的 summary／anchors／topic_lines 必须重跑，不允许"换了指针留旧摘要"；但 `summary_source=her` 的手写摘要不被重跑覆盖，只更新锚点与挂线，要跟新边界走须她自己重写。合并／拆分产生的新事件摘要由 LLM 重新生成而非拼接；话题线把旧线当候选提示重新判定、不自动继承并集。上层记忆指针不自动改写：合并顺 `merged_into` 追，拆分无法判断落点时呈现两个候选并标"已拆分"待她定，不替她猜。

## 5.8 同名概念澄清：机械修正 ≠ 记忆／表达纠正五层

`src/event/correction.ts` 实现的是上述五种**事件边界机械修正**（分区操作）。理念中的"记忆／表达纠正五层"是另一件事——她对自己记忆内容与表达风格的五层纠正机制，属待建设计（见附录 D），不得因为同名"纠正"就误以为五层已实现。事件层 params 中不得出现任何情绪、心情、重要性数值字段。

## 5.9 事件层应建模块与常量唯一出处

`src/event/` 规定十个模块：`params.ts`（全部可调参数与换算函数唯一出处，魔法数字只此一处；参数是注入点不是自动调参对象，调整只影响以后新事件）、`segmenter.ts`（机械切分，守护记录唯一归属）、`detector.ts`（闭合检测与优先级表）、`closure.ts`（后台闭合管线、两段 LLM 提示词与摘要写入）、`correction.ts`（五种修正与组合原语）、`backlog.ts`（待归并／孤儿记录与补切队列）、`ingest-stage.ts`（摄入阶段编排）、`llm-port.ts`（LLM 抽象端口，不绑定具体模型 SDK）、`raw-text-port.ts`（闭合时按指针取正文）、`tool-typing.ts`（工具轮类型化）。

集中常量（其它模块不得自带同义常量，一律经 params 换算函数取值）：`silenceGapMinutes=30`、`maxEffectiveCharsPerEvent=7000`、`fuseRawChars=50000`、`orphanWindowDays=7`、`recentWindow=10`、`minSimilarity=0.7`、调用超时 60000ms、轮预算 120000ms、`taskClosureActive=false`。

# 第 6 章　B 块记忆层：索引、布尔门、窄柄、影子与建卡通道

## 6.1 两层划分与一条方向性裁决

记忆能力分两层，性质完全不同：

- **第一层·记忆内核**：离线可测的纯逻辑——索引结构、检索算法、确定性布尔门、审计 harness，不碰宿主、不碰 fs／sqlite 连接；
- **第二层·实时接线**：把内核经窄柄接进运行回路，提供宿主无关工具集与 cordis 薄壳，引入三态灰度开关、影子观测与受控窄写。

方向性裁决：**人工 seed 通道与锚点 remap 生产代码必须整体下线。** 人工喂记忆种子、用 remap 改锚点与"她是记忆唯一主体、运行回路零人工"的信条冲突。终态要求：生产 dependencies 维持空对象；人工枚举只允许存在于测试夹具；用下面 6.2 规定的运行期建卡通道取代人工 seed，并以变异反证与后门扫描自证无残留人工通道。

## 6.2 运行期建卡通道（取代人工 seed 的核心机制）

记忆卡的产生分两类性质不同的写入，共用同一根窄写管道，但绝不能混为一谈。

**第一类：机械派生写入（无需判断，确定性、可重建）**

- 触发条件是纯结构状态，不含任何内容评价：事件达到 `status=closed` 且 `summary_quality=ready`，且其每个锚点都是合法 ULID 并能在经历真源中解析；
- 构建器对每个合格事件，取去重排序后的锚点，用 `deriveCardId(event_id, anchors)` 确定性算出 card_id，派生一张轻卡；双跑必须逐行相等、重放幂等；
- 只写可整体丢弃重建的投影 `projection/memory-index/`，绝不写 append-only 真源；没有重要性评分、不按内容挑拣，合格事件来一张建一张；
- 未闭合、未 ready、锚点悬空的事件暂时不建卡（不是"被判定不重要而丢弃"），原文仍在真源，状态合格后重建即可补上；
- 运行期由宿主 worker 在事件闭合后增量触发（记忆投影 drain），写面受单写者约束，离线构建占用写单例时运行期自动降级只读。

**第二类：她的判断写入（复盘／做梦就位后才发生）**

- 取舍、纠正、失效、遗忘、检索词等带判断的动作，由她在复盘与做梦中决定，以 `decisions.jsonl` 决策行留痕，`created_by` 只允许取值 `her`；
- 决策动作枚举规定为：`create-card`／`update-cues`／`tombstone-card`／`add-alias`／`invalidate`；账本 append-only，重建时逐条回放（tombstone→superseded、invalidate→invalid，其余动作的回放也必须实现，不得只实现一部分）；
- 在反思通道（kind=reflection）解冻、复盘产线建成之前，判断类写入不发生；**系统不设置任何运行期手动"确认／审批"按钮去替代它**，运行回路零人工；
- 自然语言检索词（cue／alias）受 K5／H7 约束，不得让模型静默生成；其自动化必须满足 6.4 的数据门槛并通过外部评审后才解冻，解冻前这些字段留空。

**选择不发生在建卡环节**：建卡全量、可重建；"此刻想起哪张"由检索布尔门在读出时裁决（宁空勿错），"作废／遗忘"由她的决策台账在重建时回放。本机制是复盘产线的下游落地件（复盘的结论经它落成卡），但它本身不是复盘，也不依赖复盘才能做第一类机械建卡。

## 6.3 独立投影 memory-index：零正文轻卡库

记忆索引是 L3 之外的**独立投影**，位于 `projection/memory-index/`，与 `fasti.sqlite` 平级、互不引用。构建器只读 `experiences/`、`events/` 的 JSONL，不打开 fasti.sqlite、不碰 state，因此宿主运行时也能离线构建，不存在第二个写实例争抢。目录三件：`memory-index.sqlite`（轻卡索引库，原子 tmp+rename 落盘）、`revisions.jsonl`（迁移/构建账本，operator 取值 `offline-cli`，append-only）、`decisions.jsonl`（建卡/选择决策台账，created_by 取值 `her`，预对齐决策格式但不是 judgment_ledger）。

SQLite 规定六张表（`src/memory/schema.ts`）：

| 表 | 作用 |
|---|---|
| `schema_meta` | 库内键值元信息，stamp 与 revisions 账本对应 |
| `mem_card` | 轻卡主表，**零正文**：禁止出现 summary／body／raw_text／emotion／mood／importance／session 等列，由守门测试固化这条禁令 |
| `mem_alias` | 检索别名（含 source='miss' 的落空补别名） |
| `mem_miss` | 漏召观测登记 |
| `mem_audit_run`／`mem_audit_item` | 离线审计的批次与明细 |

轻卡只存 card_id、event_id、权威锚点 `anchor_json`（真源经历 id 列表）、channel、类型与选择状态。她记得什么的原文永远在真源，索引里只有指针和线索——索引可随时整体丢弃重建，注入时必须回真源下钻，索引无法被当成记忆本身。schema 版本从 1 起，走 revisions 账本演进，禁止 ALTER 原地改历史行。

## 6.4 目标函数、三条质量红线与检索内核

记忆层不为"搜得快"而存在，目标函数：

> 在约束（工作窗口 ≤700 字、每轮补取 ≤1 次、装配路径 P95 延迟预算）下，最大化记忆选择与装配的质量。

三条可计算质量红线，阈值为观测期经验初值，**harness 校准前只观测、不卡发布、不写进任何自动拦截逻辑**：

| 红线 | 口径 | 经验初值 |
|---|---|---|
| R1 证据召回率 | 金标回放中目标事件出现在 top-k（默认 k=3）的比例，按冷启动分层 | ≥ 0.85 |
| R2 错误事件认定率 | DRM 诱饵对等近邻判别选错卡比例；强断言／承诺／日期／原话／否定五类高危断言单独统计 | 总 ≤ 0.05；五类高危趋近 0（0 容忍计数） |
| R3 叙事自我一致性 | 跨时间同主题提问对，装配线索支持的回答互不矛盾的比例 | ≥ 0.8；叙事线未建前按 N/A 空置，不许造数 |

700 字硬顶是结构性预算而非常数；近因衰减参数只能以具名常量给经验初值，harness 网格扫描后凭数据修订并在账本留痕。全部指标由离线 harness 计算落审计表，运行期不采集、不上报（对齐"无默认遥测"，K13）。

检索内核（`bm25.ts`＋`fts.ts`）刻意选择**平坦 BM25＋IDF 加近因先验**，不引入向量数据库或黑箱重排模型：打分可解释、可在离线 harness 复现；查询规范化（NFKC→ASCII 小写→空白折叠）是纯函数、可单测；生产零依赖，重活在离线构建期完成、运行期只读。检索结果输出带解释的 `ExplainedRankedCard`（附命中通道与分数构成）。

## 6.5 召回架构总则：两条通道，且只有两条

记忆如何进入她的回答，架构上**只允许两条通道**；两条通道之外，禁止私接任何绕开裁决、把粗召回结果直接送进上下文的旁路（这是施工红线，代码审查与变异测试必须证明该旁路不存在）。

**通道一·收严的自动召回（系统主动，门控后注入）**

1. 粗召回零件（BM25＋IDF＋近因先验）取完整候选全集——它只是通道一的内部零件，其排序结果**不允许**被直接拿去装配上下文；
2. 候选全集必须经过 6.6 的确定性布尔门裁决，强通道命中才接受、弱通道构造性拒绝、证据不足显式弃权；
3. 门接受的卡再经工作记忆窗口装配进上下文。任何"未过门的命中即返回"直通支路都属违规实现，代码审查与变异测试必须证明其不存在。

**通道二·落空自主回查（她主动，门不替她猜）**

1. 门返回 `abstain`（有候选但证据不足而弃权）或 `no-match`（词面零命中）时，编排层必须把回查机会交给她，而不是静默换成宽松结果硬凑；
2. 她可用的主动工具是只读的 `getCardsByAnchor`（按锚点翻卡）与 `resolvePointer`（序号反查后经宿主门面下钻真源原文）；内核不越界读正文；
3. 她确认目标卡后可经唯一卡写 `addMissAlias` 补一条 source='miss' 检索别名（只进检索别名、不改展示线索），下次同一问题即可被通道一召回；同时 `recordMiss` 登记本次落空的客观事实；
4. 她也查不到才算真没有：本轮不认定、不编造，按落空纪律留观测。自主回查的实时接线是强制建设项，其任务优先级已前置为裁决前置批（见第 11.5 节 #115 与附录 E）。

两条通道共用同一份记忆索引与同一组窄柄；区别仅在"系统自动递"还是"她主动取"。检索分数不等于事实置信度，任何通道都不得把排序分当作事实判断。

## 6.6 通道一的裁决器：确定性布尔门

召回侧核心立场八个字：**正确性优先、宁空勿错。** 不用连续证据分和需小样本标定的 cutoff，而用确定性布尔规则裁决，因此不存在会退化的 coverage 公式。门策略（`GATE_POLICY`）把命中通道分两类：

- **强通道**：`exact-alias` 恒过；`fts-substring` 子串需再过 ASCII 词边界；
- **弱通道**：`like-fallback` 的宽松子串构造性拒绝。

词边界区分字符集：查询含任意非 ASCII（中文等）时边界不适用、直通不惩罚中文；纯 ASCII 查询枚举每次出现，前后邻都不是 token 内字符（或抵达串端）才算边界成立（"用git提交"能命中、"gitflow"不误中"git"）。门是接收候选数组的**纯函数**，不 import bm25／store／builder 以防成环，无 I/O、无 Date.now()，时钟与数据全部入参注入。关键语义：**abstain（门主动弃权／无合格证据）不等于 no-match（检索没找到）**，两者 reason code 不同，下游据此决定闭嘴还是触发自主回查。

## 6.7 运行期窄柄：恰六个方法

`src/memory/runtime.ts` 的 `openMemoryRuntime` 返回装配层唯一可持有的 `RuntimeMemoryHandle`，**恰六个窄方法**：

1. `searchExplained(query)`：可解释检索，委托时写死 `limit:undefined`，入参类型没有 limit 键——让预截断在类型层不可表达；
2. `getCardsByAnchor(experienceId)`：按锚点反查卡；
3. `addMissAlias(input)`：唯一卡写，补 source='miss' 的检索别名，sensitive 在包装层固定为 1，入参类型不含 sensitive，危险选项无法表达；只读降级时抛 UnavailableError；
4. `recordMiss(input)`：漏召登记落 mem_miss（观测写，非卡写）；
5. `recordShadowObservation(input)`：影子观测写，落 `memory-shadow/` JSONL，term 内部算 sha256、**原文不落盘**，与 sqlite 物理隔离，只读降级时仍可写；
6. `close()`：关闭句柄。

纵深防御纪律：返回值必须是只挂六方法的新对象字面量，完整后端柄永不离开闭包；窄类型不 extends 读／写柄，字符串拼接键与运行时反射也只能看见窄方法；模块自身不 import node:sqlite／node:fs，连接生命周期封在 store 后端；写单例被离线构建占用时自动降级只读，读方法照常、写方法抛 UnavailableError，绝不抢锁。

## 6.8 工作记忆窗口、别名、漏召与影子落面

- **工作记忆窗口**（`window.ts`）：吸收 LlamaIndex waterfall 思路，按槽位组织每轮注入线索，硬顶 700 字、单轮至多一次补取；槽位编排与具体参数属待评审定稿项，不得在实现中擅定。
- **别名窄写**（`alias-write.ts`）：无环低层，写柄仅通过单向委托暴露，运行期读柄不扩权；生产别名写只在门 on 态生效，off／shadow 态卡写返回 deferred、不落生产。**定性：miss 别名是检索索引层线索，不是记忆内容或价值判断**——零正文、可整库重建、每卡 active miss 上限常量 `MAX_MISS_ALIASES_PER_CARD = 5`（`alias-write.ts:27`，超限返回 `alias-cap-exceeded`），因此不适用 B 块"多次印证才固化"约束；她在通道二对目标的确认是写入前置动作，系统仍不做自动扩写。
- **漏召观测**（`miss.ts`）：门返回 abstain／no-match 时登记客观事实，作为通道二自主回查编排的触发凭据并供离线分析；它只登记、不触发系统自动扩写，回查动作必须由她发起。运行期实时接线（当前内核仅有零件、编排尚未接线）是强制前置建设项，不得长期空缺。
- **影子窄写**（`shadow-write.ts`）：shadow 态旁路观测的落面，只持久化六个无正文字段——规范化词项 sha256、粗召回候选数（门过滤前的全集计数）、门状态、门接受数、拒绝原因码、时刻；写失败隔离为 ok:false，绝不阻断主链路。
- 其余内核零件：`content-hash.ts`、`invalidate.ts`、`ledger.ts`、`serial.ts`、`builder.ts`、`memory-errors.ts`、`bm25.ts`、`fts.ts`、`gate.ts`、`store.ts`、`schema.ts`、`window.ts`、`miss.ts`、`alias-write.ts`、`shadow-write.ts` 等共同构成记忆内核，纯内核不碰 fs／sqlite。

## 6.9 审计 harness 与信息污染防护四层

`src/memory/audit/` 规定离线评测套件，全部不依赖线上流量：`fixtures.ts`（金标夹具加载与版本校验）、`gold.ts`（R1 证据召回回放）、`decoy.ts`（DRM 诱饵对与 R2 错误认定）、`consistency.ts`（R3 一致性探针，未就绪前空置规则）、`provenance.ts`（抽样溯源，窗口内锚点解析率必须 100%，否则硬失败）、`four-state.ts`（门后四态度量）、`metrics.ts`（指标聚合、bootstrap、随机源与落库低层）。

信息污染防护四层必须各有零件对应：

1. **来源分级**：按 provenance 给证据分级，诱导／外部信号权重最低；
2. **诱饵防护**：DRM 诱饵对等近邻判别，专测她会不会被灌进来的假记忆带偏；
3. **检索闸**：布尔门弱通道构造性拒绝，abstain 与 no-match 分开；
4. **指纹核对**：内容哈希与盖章指纹一致性核对。

污染"检得出、记得到"之后的处置流程属待建设计，不得在本层擅自实现自动处置。

## 6.10 L5 装配与 M6 开门上锁

`src/assembly/` 是内核与宿主之间的隔离带，规定三件：`memory-tools.ts`（宿主无关的工具集纯内核，不 import node:fs／node:sqlite，窄柄、粗召回零件、影子落点、时钟全部构造注入；对外 DTO 逐字段白名单投影，只回 cardId／序号／锚点／线索／门原因，绝不回显 sensitive、内部别名列、contentHash 或原始查询；内核只暴露门控检索一个对外入口，不注入任何绕门直通端口）、`host-tool-runtime.ts`（宿主工具运行时抽象，真机能力只在此绑定）、`index.ts`（装配入口与 `runGatedSearch` 编排）。

装配层是唯一被允许实例化记忆运行时的地方，采用独立装配目录加默认拒绝白名单；投毒矩阵必须先红后绿，自证对话链路 import 不到记忆层、记忆层 import 不到门面，任何新增反向依赖都被编译期与反射守门测试拦下。自动建卡接线前必须先产出装配层依赖设计（适配器装配或独立新模块），不得绕过 M6 直接接线。

# 第 7 章　宿主适配、三态灰度门与发布规程

## 7.1 L6 适配层：薄壳七件套

`src/adapters/dsh/` 把纯内核接到 cordis／dsh-llm 宿主，规定七个模块：`plugin.ts`（插件入口与生命周期、解析配置、接线记忆门三态）、`convert-event.ts`（宿主会话事件到经历条目的转换）、`event-types.ts`（宿主侧事件类型）、`host-model-route.ts`（模型路由，不含 sessionId，见 K12）、`llm.ts`（dsh-llm 端口适配与闭合 worker 启动）、`memory-tool-bridge.ts`（四工具 defineTool 桥接薄壳）、`index.ts`（适配层导出面）。适配层是薄壳：所有业务判断在内核与装配层，L6 只做协议翻译与生命周期管理，把宿主 SDK 升级影响限制在这七个文件内。

## 7.2 三态开关 memoryGateMode 的精确语义

配置项 `memoryGateMode` 取值 `off`／`shadow`／`on`，**缺省 off**，非法值解析时直接抛 TypeError。运行期不得自行翻转，切到 shadow／on 属显式授权动作。系统中**不存在"松召回直通"这第四条路径**：粗召回 BM25 只是门的内部零件，任何状态下都不允许把未过门裁决的候选直接注入上下文。

- **off（生产默认·记忆整体停用）**：不注册任何记忆工具，上下文装配不含记忆注入，行为等同于尚未安装记忆能力；不触窄柄、不写影子。这是产品内的一键回退位——回退到"无自动记忆"，而不是回退到某个宽松检索器。
- **shadow（影子试运行·门空跑不发话）**：注册同一组工具以获得真实查询流量，但 `gatedSearch` 的门裁决结果**不装配进上下文**——对外统一返回空信封。**空信封 DTO 形状在施工前定死，不给实现方自由发挥**：①`status` 取新枚举值 `observing`（不复用 `legacy-ok`）；②`cards` 恒为空数组；③`reason` 可选；工具 description 必须显式声明"观测期检索不可用"，shadow 单测断言该 DTO 形状。同一次调用在内部完整执行"粗召回全集→布尔门裁决"，仅把无原文观测（含 `countScope` 口径标记）写入影子落点，用来在真实流量上度量门上岗后会放行/拒绝什么；门或影子落点的任何异常都被隔离，绝不阻断主链路；此状态一切卡写返回 deferred、不落生产，只读回查工具可调用但不产生生产数据。对话层副作用（模型是否复述"暂无记忆"、是否反复重试）属第 10 章登记的开放项，转 on 前专项观察；结构定形不等待话术拍板。
- **on（转正·两分法上岗）**：通道一门控自动召回的结果经窗口装配进上下文，通道二自主回查工具同时对她可用；生产别名写仅此态生效。注意窗口自动注入链路当前**尚未接线**（`assembleWindow` 零调用点，现状为模型手调工具），接线是独立任务 #116，不得在 #114 验收中假设其已生效。

### 影子模式在对照什么、转正后变什么

影子期不存在"两套对外结果"，对外始终无记忆注入；对照发生在观测层：同一条查询，分别记录**粗召回全集**（门过滤前的候选）与**门裁决结果**（接受/弃权/无命中及原因码），落盘为六个无正文字段——规范化词项 sha256（不留原文）、粗召回候选数（带 `countScope` 口径标记）、门状态、门接受数、拒绝原因码、时刻。离线 harness 与影子数据据此统计四态（粗召回与门都接受、粗召回有但门弃权、粗召回漏而门内反查可补、两者都空）下的 R1／R2 表现，统计只取同口径段样本；全过程无自动记忆注入、无生产卡写，但模型可见一个恒空工具的对话层反应不得默认为零扰动，按第 10 章开放项观察。

**转正（on）后变化的是"门的结果开始参与回答、通道二对她开放"**；数据不会被反向改写或删除。回退语义是"**门回退、数据写留存**"：一键回到 off 后记忆注入停止，影子与审计数据保留备查、不做反向删除。转正是可逆灰度，不是一次性迁移。

## 7.3 四工具桥与宿主无关内核的分工

先落地宿主无关的工具集内核（`MemoryTools` 四方法）：`gatedSearch`（**唯一**检索入口：粗召回全集必经布尔门裁决后返回统一安全形状，不存在绕过门的直通返回）、`getCardsByAnchor`（按锚点取卡，通道二只读零件）、`resolvePointer`（序号反查 cardId，真源内容下钻仍走宿主门面、内核不越界）、`addMissAlias`（落空补别名，门未开回 deferred）。再由 `memory-tool-bridge.ts` 用宿主 `defineTool` 包薄壳注册给 function-calling。静态门保证内核禁宿主包、不引 node:fs／sqlite；安全 DTO 保证模型侧看不到 sensitive、内部列名、contentHash 与原始查询。

## 7.4 转 on 的量化门槛、漂移与回退

默认 off 不是永久状态，但翻转必须**全部满足并经显式人工授权**：

1. 四态样本各 ≥ 200 条，或灰度运行 ≥ 2 周，取晚者；
2. 未解释回归为零；
3. 探针、投毒、变异测试全部通过；
4. 显式人工授权；
5. 保留一键 off。

真值指纹漂移用二分策略：冻结硬原语不动，在策略层二分定位是真源变化还是索引损坏；staleness 要有明确观测口径。生产重建与影子重建分开，影子重建执行者落在装配层之外、保持装配 fs-free。重置协议与别名审计撤销协议必须登记；撤销写入在首期可以不实现，但缺口要显式挂账，不得假装已具备。

## 7.5 真机验收规程

真机验收无法用离线测试替代，必须在**隔离 `DSH_HOME`** 中进行，全程不碰真实数据根：隔离 profile 打通最小 LLM 调用 → 以 shadow 态装插件 → 验证四工具可见性、function-calling 路由与信封、生命周期与句柄、影子落盘与数据根边界、peer 版本实配 → 证据脱敏、真实根零写复核、清理隔离环境。离线单测发现不了的宿主协议问题（如工具注入路径）只能在真机暴露，修复同样走 TDD 并补回归用例。

# 第 8 章　C／D／E 三块的设计约束（未建块的强制前提）

本章不杜撰尚未定稿的内部机制，只规定这三块开工时**必须满足**的约束与前置；详细机制在各自立项设计中产出并回写本文件。

## 8.1 C 块主动系统

- 动机不能由系统注入，优化必须发生在她的判断之后；禁止常驻调度器与进程内 cron（K3），主动触发复用外部 tick 或显式事件。
- 首期范围是五件事：C1 主动合成轮（带来源标记的合成轮走同一只读管线，**主动信号绝不写入真源**）、C2 防打扰两层决策与概率门（冷启动静态阈值，后续只收紧不放宽）、C3 非常驻任务表与重启回灌标记（任务表可重建）、C4 两遍生成 Planner／Replyer、C5 编辑下轮生效与只读白名单（运行期无热改写，对齐 Letta 机制）。
- 硬前置：C1 必须等反思通道、任务闭环激活、记忆门转 on 三个前提齐备；首期只经 L6 发声通道主动起话头，不接任何 D 类能力；一旦要接不可逆写或对外影响，D 的四档授权加审计／回滚／紧急制动必须先行。

## 8.2 D 块身体·权限·制衡

- 展开四档授权：只读／可逆写／不可逆写／对外影响，每档门槛不同，权限随她自己长出的价值观分级开放。
- X7 四件套必须与能力**同批设计**：审计、回滚、紧急制动、用户最终否决权，缺一不得发放对应能力。
- 适配器接入顺序预判：qq → browser → camera；多模态真机（图片／语音／视频精确字段）归 D。

## 8.3 E 块身份连续性

- 跨设备／跨平台转移重做（X8）；同一性由三维共同定义（X9）：**原文连续／叙事连续／指针网络连续**，自我叙事线只解决"叙事连续"一维，不能替代整个 E 块。
- 工程唯一内核预留点：tick 从单进程 max+1 升级到 HLC 或 ULID（见 2.7）。
- M9 隐私：跨设备转移能力是真删除闭包的前置，未就位前隐私内容无法闭环真删。

## 8.4 复盘、做梦、遗忘与自我模型的内容产线约束

- **反思通道**：kind=reflection 的写入通道是复盘、叙事、主动合成的共同枢纽，未解冻前这些判断类产线不得运行。
- **复盘三层**：选材（输入是经历流）→ 反思（产出 kind=reflection 写真源）→ 固化为卡或台账；judgment 台账只是投影不是真源。筛选权归她，复盘要有可表达决策的字段出口。
- **做梦**：kind=dream 的内省遍历，非自动、非定时（受 K3 约束）；**自我提炼归做梦、不进每日复盘**。
- **自我模型**：facts 七态、倾向强度与因果边；倾向可升可降、可被做梦重写；K7 禁情绪数值，但倾向强度是另一回事、允许量化。
- **真遗忘**：删除闭包（见 4.7），含级联与备份策略；冲突的历史 ADR 文字必须在删除能力动工前订正。
- **反馈纪律**：反馈按倾向而非禁令处理，单次是弱信号，不做硬否决。

# 第 9 章　横切工程规范

## 9.1 TDD、变异反证与"不采信自述"

- **TDD 先红后绿**：每个机制先写失败测试再实现，关键项亲跑；测试用例基线只增不减。
- **变异反证**：仅"测试通过"不够，必须主动对生产代码做变异，证明测试真能抓错，并留反证脚本与日志（日志经 .gitignore 不入库）。
- **不采信自述**：审核方独立回代码、跑验证，"我已修好"的口头结论无效，必须给可复跑的原始物件。
- **全量门禁**：构建＋类型检查＋全量测试必须全绿才可进入提交评审。

## 9.2 真实数据根零写入

真实数据根是她的真实经历，开发期红线为零写入：全部测试使用临时目录或隔离 `DSH_HOME`；离线脚本默认 dry-run，真写必须显式追加 `--apply`，并先打印真值指纹与 diff、要求二次确认；大改动前后比对真实根文件清单与时间戳；任何对真实根的写删都须先给影响清单、先冷备、再取得显式授权。git 的 add／commit／push 同理须显式授权。

## 9.3 离线脚本职责

应提供的离线脚本类别：事件补切回填、raw-turns 迁移与迁移自检、实时会话模拟、记忆索引离线首建／重建、四态审计与红线度量、变异反证、冻结面守门核验、实时面核验。所有带写操作的脚本默认 dry-run。

## 9.4 "虽流行仍不做"冻结清单 K1–K13

任何实现引入即驳回；带触发条件者必须先凭数据满足条件、走外审才能重议。

| 编号 | 禁止项 | 重议口径 |
|---|---|---|
| K1 | 向量检索／embedding 硬依赖 | 连续两个审计周期语义漏召越 R1 且词法改造收益证穷尽 |
| K2 | 图数据库／实体图投影 | 卡量过千且多跳问题占比 >30% |
| K3 | 常驻调度器／进程内 cron | C 块立项且外部 tick 被证不可行，附单实例锁方案 |
| K4 | 真源原地更新 | **永不重议**，只允许追加新版本 |
| K5 | LLM 静默改写已存事实／卡 | **永不重议**，只能经她的决策留痕生成新决策行 |
| K6 | 黑盒检查点／状态快照 | 不设触发，检查点必须白盒可读 |
| K7 | 情绪／心情／重要度数值入契约 | 内核契约永不加列；倾向强度另算，情绪至多进投影且需外审 |
| K8 | 在线校验器／摄入热路径 LLM 判定 | 离线 harness 用数据证明离线延迟不可接受 |
| K9 | 概念满铺（先建空表空接口） | 每个新投影独立立项＋金标＋重建协议 |
| K10 | 逐层路由器／查询分类器 | 平坦检索连续失守且错误分析定位到路由缺失 |
| K11 | 周期性全量重算替换增量 | 仅指纹对账发现损坏时的一次性修复 |
| K12 | 会话字段进真源 | 不设触发，sessionId 不入库 |
| K13 | 默认遥测／埋点外发 | 审计始终本地落库，外发需合规评审加显式开关 |

外部框架原则是"只吸收机制、不搬实现"：可吸收双时间纯函数失效、候选序号化、槽位 waterfall、编辑下轮生效与只读白名单、迁移账本等机制，同时显式拒绝其重依赖、事实堆与自由文本改写。

## 9.5 生产零依赖与确定性降级

生产 `dependencies` 必须为空对象，宿主能力全部走 peerDependencies，使攻击面与升级面最小。每个外部依赖断点都要有确定退化姿态：SQLite 不可用→JSONL 投影；索引库被离线任务占用→运行期只读；LLM 端口缺失→事件照常闭合、摘要 pending。

## 9.6 备份与恢复

备份最小集必须覆盖全部不可再生正本；**备份不做真实恢复演练等于没备份**，必须安排一次真实恢复演练作为门禁（而非仅验证备份文件存在）。

## 11.2 施工流程与取号规则

1. **设计方案**：主控先出某块设计方案，外部多 AI 评审，主控逐条裁定采纳／不采纳并说明理由，冻结最终方案；机制变更回写本文件正文，理念变更必须先过 1.8 节理念红线锚点。
2. **实现方案**：主控出实现方案，外部实现方提问／建议，往返修订，实现方确认无疑后冻结最终落地方案。
3. **编码与评审**：外部实现方编码，主控评审、退回修改直至通过；每过一道闸门、每次裁决都要回写本章状态。
4. **闭环与授权**：涉及提交推送、真实数据根写删、冷备 `--apply` 等动作，必须用户**显式授权**后才执行。
5. **取号**：新任务先取号再进 11.4 总表，不允许口头挂活。**当前最大号 #116，下一个 #117**；状态变化同步改本表"阶段／状态"两列，不留两套口径。

## E.1 裁决结论（一句话）

记忆召回只保留她最初设计的**两条通道**：收严的自动召回（通道一）与落空后的自主回查（通道二）。实时装配层中绕过布尔门、把粗召回结果直接送进上下文的"绕门旧路"**全部删除**；记忆本门控检索收编为唯一自动召回入口，影子机制保留但重新定义为同一条通道一的空跑观测状态，不再是第二条回话路线。

## E.2 背景：为什么会存在旧路，为什么现在拆

### E.2.1 两条通道本就是立项原型

召回门提案的立项原型即两分法：

- **G-1（通道一）**：粗召回取候选全集，确定性布尔门按"宁空勿错"收严，强通道才放行，弱通道构造性拒绝，证据不足显式弃权；
- **G-2（通道二）**：门返回 abstain／no-match 后，由她走宿主门面对真源做自主回查、沿锚点下钻原文，确认后补一条 miss 检索别名；查无才算真没有，不编造。

### E.2.2 旧路的历史身份与三个临时职责

记忆层建设期间，实时接线保留了一条绕门支路：装配层 `LegacySearch` 端口绑定门面 `Fasti.search`（A 块经历投影上的关键词子串检索），off／shadow 态的主返回直接采用其结果。它当时承担三个临时职责：

1. off 态对线上行为零变化；
2. 为影子试运行提供"旧路实际返回"对照基准；
3. 保留一键回退到松召回的能力。

裁决：该支路是记忆层未建成期的临时代步，不符合两分法定稿拓扑，三个临时职责改由 E.4 的新三态与观测设计承担，旧路整体拆除。

### E.2.3 "把老路改造成新路、删除记忆本"方案的否决记录

评估过另一方向：在 `Fasti.search` 经历全文检索末端加过滤、废弃 memory-index。结论为**否决**。两者是不同资料库上的两套模型：

- `Fasti.search` 检索 A 块经历投影，对象是含原文片段的经历条目，返回 id／kind／channel／snippet；
- 门控检索检索独立的 memory-index，对象是零正文记忆卡（mem_card），布尔门自设计第一天即建在记忆卡之上。

在老路上加门会同时废弃：记忆卡与锚点反查、`decisions.jsonl` 决策台账（墓碑／失效／未来真遗忘的落点）、运行期机械建卡通道、miss 别名、R1／R2／R3 审计 harness、通道二全部工具，并使复盘、做梦失去落地载体。正确方向是反向收编：记忆本门控成为唯一入口，粗召回降级为其内部零件。

## E.3 最终拓扑：两条通道、三重链、零旁路

### E.3.1 两条通道（且只有两条）

- **通道一（系统主动）**：粗召回零件取全集 → 布尔门裁决 → 工作记忆窗口装配。未过门裁决的候选不得进入上下文。
- **通道二（她主动）**：abstain／no-match 时编排层把回查机会交给她；只读工具 `getCardsByAnchor`、`resolvePointer` 沿三重链下钻，确认目标后经唯一卡写 `addMissAlias` 补 miss 别名，`recordMiss` 登记落空事实。

两条通道之外禁止私接任何绕门旁路；该禁令须由静态结构门与变异测试长期机器化守护。

### E.3.2 三本与三重链式反查保持不变

- 记录表（原话）＝ raw-turns 真源；记事本（摘要）＝ experiences 真源；事件层 events 是**二级真源**——写入即固化、不可由算法批量重建（与 5.1 表述一致），不承受任何"可重算"语义；记忆本（关键词）＝ memory-index 的零正文 mem_card。
- 反向三重链：记忆卡（anchor_json 经历 id）→ 经历摘要（门面 query）→ 原话（经历 Pointer 经门面 resolvePointer 取 raw_text）。内核不越界读正文，正文下钻只走宿主门面。

### E.3.3 三态是同一条通道一的工作状态，不是三条路

| 状态 | 工具注册 | 自动记忆注入 | 影子观测 | 生产卡写 |
|---|---|---|---|---|
| off（默认） | 不注册 | 无，等同未安装记忆能力 | 不写 | 不生效 |
| shadow | 注册（真实调用触发空跑） | 不注入，gatedSearch 对外回形状定死的 `observing` 空信封（DTO 见 7.2） | 写六字段无原文观测＋`countScope` 口径标记 | 一律 deferred |
| on | 注册 | 门裁决结果经窗口注入；通道二同时可用 | 可继续采样 | 仅此态生效 |

- off 是产品内一键回退位，回退到"无记忆"而非"松召回"；
- shadow 不再存在"旧路主返回＋新门旁路"两套对外结果，只有一条门控路在空跑；
- 运行期不得自行翻转状态；shadow→on 仍受 Q4 门槛与显式授权约束，回退语义维持"门回退、数据写留存"。

### E.3.4 影子六字段（更名后口径）

落盘字段固定为：规范化词项 sha256、**粗召回候选数 candidateCount（门过滤前全集计数，原 legacyCount 更名）**、门状态、门接受数、拒绝原因码、时刻。termNorm 与原始查询不落盘。Q4 四态统计口径相应改为：粗召回与门都接受／粗召回有但门弃权／粗召回漏而自主回查可补／两者都空；样本门槛（四态各 ≥200 条或灰度 ≥2 周取晚者）与探针、投毒、变异测试要求不变。

## E.4 删除面、更名面与留存面（施工对照清单）

### E.4.1 拆除（实时绕门支路）

**同源新增：只读 `sourceLookupPort`（取代被删端口，不是新增暗道）。** 拆除 legacySearch 后，通道二第②③跳（经历摘要、原话下钻）必须仍有合法通道，由本端口承接，规则一次定死：

## E.5 通道二实时接线：强制前置项

现状：通道二零件齐备（按锚点取卡、序号反查、补别名、落空登记内核均在），但"abstain／no-match 出现即把回查机会交给她"的运行期编排未接线，`recordMiss` 运行期零调用。

裁决：

1. 通道二实时接线拆为独立施工任务（#115），与绕门支路拆除（#114）**同批次推进**，优先级前置于写入闸、转 on 等长尾任务；
2. 接线内容：门返回 abstain／no-match 时的编排钩子、落空台账运行期启用、只读回查工具（含 E.4.1 新增 `sourceLookupPort` 的摘要／原文两跳）与 miss 别名写入的状态门禁（仅 on 态生产写）、失败只入案底不阻断对话；
3. 仍守 N14 安全 DTO 与窄柄边界，编排层不得持账本句柄、不得读正文。

**recordMiss 先于写入闸 #90 上线的豁免条件（四条同时成立，缺一不可）：**

1. `mem_miss` 位于 `projection/memory-index/memory-index.sqlite`，是**可重建抄本而非真源**——store 后端不打开 `fasti.sqlite`，不封装任何指向 experiences／events／raw-turns 的写函数；
2. 只存规范化词面 `term_norm` 与 `term_hash` 等白名单六字段——**她的检索词会以 norm 词面落库**（这是已知隐私面，故原始查询全文永不落盘、词项另存 sha256），不含正文、不含上下文；
3. 生产写仅 on 态产生；off／shadow 态一切卡写与 miss 写 deferred，不生效；
4. 重建时构建器对 `mem_miss` 原样搬运（`copyRows`），历史观测不抹不重算。

**依赖关系定调（防止排期卡死）**：#115 的前置对象是**接口契约**（窄柄六方法与 sourceLookupPort 的形状），不是写入闸本身；#90 未建成前 #115 允许在 off／shadow 态完成接线与空跑验证，on 态生产写的放开随 #90 闸门收口，不得反向要求 #90 先于 #115 完工。

**强制挂账（必须做、可后置，不许只写"后续观察"）**：`mem_miss` 无配额、不去重、重建原样搬运，无限增长会拖慢 rebuild。必须单独立卡制定留存上限（按行数或天数的保留／压缩策略），在转 on 之前闭环。
