## 2. 我方材料的认账项（代码核验后确认评审对、我们错）

### 认账 1：把"门方向反了"当核心病根不准确——召回层先归零，门作用在空集上

R2 的核心反驳成立，且已用最小 FTS5 实验实证（trigram 分词，与生产 `schema.ts` 同款）：

| 查询 | 码点 | FTS 候选数 |
|---|---|---|
| 我那个重庆酒店的发票抬头写错了怎么办（真人整句） | 18 | **0** |
| 重庆出差（模型可改写出来的短语） | 4 | 1 |
| 发票（2 字） | 2 | **0** |
| 成都（2 字） | 2 | **0** |
| 带老人去成都的行程（真人整句） | 9 | **0** |

代码链路（`src/memory/bm25.ts:114-144`）：

- 查询规范化后 **≥3 码点才走 FTS**，且是把**整句包成 phrase 做 MATCH**——要求查询的全部 trigram 在 cue_text 里连续出现，等价于"整句是 cue 的子串"；
- <3 码点或 MATCH 失败时，回退 SQL 只查 `mem_alias`（`LIKE ... ESCAPE`），**不查卡表**；零别名时 like-fallback 永远无候选；
- `exact-alias` 也只查 `mem_alias`。

结论：零别名的库里，卡候选**只有 FTS phrase 一条路**。16 条真人问法与 cue 的最长共享片段普遍只有 2 字，FTS 层候选就是 0，`gate.ts::judge` 根本没被调用。**单纯把门的 `indexOf` 方向反过来，候选仍是 0，行为零变化**。原材料 P-1 与 P-2 是"串联漏斗"不是并列问题，R2 此判定正确。

### 认账 2：P-4 对 H7 的描述失实

R3 指出的自相矛盾成立。复核 `cue-derive.ts:57-67`：

```ts
function hitsH7(raw, normalized, summary) {
  // 仅当 form ≥20 码点 且 summary 字面包含 form 时才丢
}
```

H7 **只拦截"≥20 码点且在摘要里逐字出现"的长 KP**，对 <20 码点的短词完全不生效。真机事件 1 那条 19 码点 KP 是被 `CUE_MAX_COUNT=3` 的 `slice(0,3)` 截掉的，不是 H7 丢的。原材料 P-4 写"19 码点长 KP 不参与反查"归因错误。R1 附带提醒也成立：**若未来 cue 改成短关键词，H7 会把新词形全部误杀，必须随契约重定义而非调参数。**

### 认账 3：生产态与实验态必须分开表述（R3 C-1）

生产库当前 2 张卡 `display_cues_json=[""]`（空占位），**生产检索面实际为空**；0/16 是"若开启 v2 派生 + 现门"的实验态结论。原材料 §9 虽有一句带过，但正文叙事容易让人误读为生产现状，后续文档须把两个数字严格分开。

### 认账 4："宁空勿错"在召回≈0 时是空真论证（R1 J-1、R3 C-3）

精度从来没被测过（16 条全是正例、零诱饵），recall=0 时 precision 恒为 1 没有意义。这个哲学批评成立：**先要有非平凡召回，精度论证才有对象。**

## 5. 三方分歧（一个真问题，三种解法）

**焦点：关键词/片段从哪来，门要不要升版。**

| 方案 | 出处 | 做法 | 代价/风险 |
|---|---|---|---|
| 甲：摘要环直接产关键词，事件加字段冻结 | R1 | closure prompt 同时产出关键词写入 EventRecord 新字段；派生环只做 NFKC/去重/截断 | 契约加列、过 parseEvent 与静态门；模型输出在写入时冻结，确定性精神保留 |
| 乙：改 key_points 书写契约为`词面｜叙述`双段，不加字段 | R2 | 摘要环按格式写 KP，派生环只 `split`；门一行不改，召回层新增机械 2–4 字窗口倒排表 + 同卡 ≥2 词面交叉 + df 上界 | LLM 不守格式需 fail-closed 降级；旧事件要兼容分支；新词面表须纳入 contentHash |
| 丙：cue 形态不动，查询侧机械枚举 2–6 字片段 + DF 稀有度 + 唯一/交叉证据，门升 v2 | R3 | `GATE_POLICY.version→2`，非对称双向：DF=1 强片段直接放、否则同卡 ≥2 片段交叉；纯数字/单字不作唯一证据 | 门语义变更需全套红测与诱饵认证；abstain 语义变化需版本化观测 |

三者共同前提：**不依赖中文分词器、不调模型做运行期抽取、不用连续分值**。差异本质是"把语义工作放在写入侧（甲/乙）还是读出侧（丙）"。

另有 R3 独有的第四条路——**时序通道** `fasti_memory_recent(limit)`：像"你还记得上次聊了什么吗"是时间主张不是词法主张，任何词法门都救不了；该通道不做相关性断言、不触犯宁空勿错。R1/R2 未反对，建议单独立项评估。

## 6. 第 0 步离线实验：已执行，结论与三份评审的预期都不同

脚本：`tests/memory/cue-arm-bench.ts`（untracked，不入库），日志 `tests/memory/cue-arm-bench.run.log.txt`。
数据：8 桥段的真模型 summary/key_points 逐字取自 `iso-write-line.real-run.log.txt`，零重造；cue 走真实 `deriveCuesFromKeyPoints`；候选与门走真实 `searchCardsExplained` + `applyGate`；**生产码一行未改**。库为内存 FTS5（trigram，与 `schema.ts` 同款）。

| 臂 | 机制 | 候选层归零 | 正确卡召回 | 误召（非正确卡） |
|---|---|---|---|---|
| P0 | 真人整句 → trigram | 16/16 | **0/16** | 0 |
| P0′ | 模型改写短语 → trigram（SCNet-Max 实跑） | 14/16 | **2/16** | 0 |
| P1o | 人工 oracle 短词 → trigram | 16/25 | 9/25 | 0 |
| P2s | 真人整句 → 全表扫描 | 16/16 | **0/16** | 0 |
| P2s′ | oracle 短词 → 全表扫描 | 2/25 | 23/25 | 0 |
| P3s | 真人整句 → 枚举 2–6 字片段 + 子串匹配 | 0/16 | **16/16** | 6 次 |
| P3d | P3s + df 稀有度 + 同卡 ≥2 片段交叉确认 | 0/16 | **16/16** | 4 次 |

### 6.1 结论一：模型改写查询这条"零代码前置臂"被实测否证

R1 J-3 / R3 PF-4 都主张"先让宿主模型把自然问法改写成短词再打现门"。实跑 SCNet-Max 后改写质量很高（`发票抬头更正`、`会议室面积`、`国庆成都行程`），但只命中 **2/16**，且这 2 条命中的都是 `await` / `async`——恰好是 cue 里连续出现的 ASCII token。

原因是几何错配，不是模型不行：改写产出的是**语义概括短语**，cue 是**叙述句**。`发票重开` 与 cue`询问发票能否重开`（"发票"和"重开"隔着"能否"）、`会议室面积` 与 `询问会议室所需面积`（隔着"所需"）——整串不连续，phrase MATCH 必不命中。**这条臂在中文上不可用，应停止投入。**

### 6.2 结论二：2 字死区是机制造的，不是数据造的

同样是 oracle 短词：trigram 9/25，全表扫描 23/25。归零的 16 条几乎全是 2 字词（成都、奶茶、王工、面积、荷花、国庆、三天、行程…），这些词在 cue 原文里**确实存在**，只是 trigram 切不出三元组。剩余 2 条失败（`锁库`、`长满一半`）才是真语义鸿沟（cue 写作 `database is locked` / `长到一半`），任何词法机制都救不了，只能靠别名。

附带纠正一个直觉：`长满一半` 4 个字也照样归零——**决定命中不是长度而是"是否为连续子串"**。

### 6.3 结论三：唯一把自然问法从 0 救到全中的是"读出侧片段枚举"，且不必动 cue 形态

P3s/P3d 对**原始叙述型 cue、零改写、零模型**做到 16/16。这意味着用户设想的"cue 只存纯关键词"这一半**不是必需的**——cue 保留叙述句反而提供更多可撞的词面。真正要改的是匹配几何：把整句查询切成 2–6 字片段去撞 cue，而不是要求整句连续。

误召侧：P3s 6 次 → P3d（df==1 强证据 + 同卡 ≥2 弱片段交叉 + 纯数字不作唯一证据）4 次。方向正确但**降幅有限**，原因是本库仅 8 张卡，`df==1` 太容易满足；生产的稀疏导数必须在真实卡片规模上重新标定。

### 6.4 本次实验的效力边界（不得当结论用）

- 8 张卡、16 条查询、单通道，**不含任何诱饵样本**，所以"误召 4 次"只能当方向信号，不能当误报率；
- 停用表是手写的 30 词左右闭集，未做敏感性分析；
- df 分布与生产 10²–10⁴ 规模不可比，`df==1` 判据在小库上偏宽；
- 所有臂都在"cue 已按 rules-v2 派生"的前提下跑，生产当前仍是"空 cue 占位"，两者不可混说。

## 7. 建议的推进顺序（按第 0 步数据修订）

原计划"先做零代码改写臂"已被否证，顺序调整为：

**第 1 步（推荐先做，收益最大且不动 cue 契约）**：读出侧片段匹配的最小实现 + 三段漏斗可观测性
- 整句查询枚举 2–6 码点片段（去停用闭集）→ 候选由**确定性扫描**产生（弃 trigram 候选层，或 trigram 仅作加速且允许 2 字走扫描）；
- gate 升 v2：片段证据制（df==1 强放行 / 同卡 ≥2 交叉 / 纯数字不作唯一证据）；
- 必须做**单调超集校验**（旧门放行的卡不得回归）与 `GATE_POLICY.version` 进 shadow 行；
- 精度验收用定向诱饵（D1 共享泛词 / D2 同形异义 / D3 纯数字），不用 16 条全正例。

**第 2 步（独立、低风险）**：叙述回读窄面（`card.eventId` → 事件当前版本 summary，带 provenance 与截断上限）。这一步与召回解耦，可并行。

**第 3 步**：别名通道强化（2 字词与语义鸿沟的唯一确定性桥），仍走手动 add_alias，不自动写。

**不建议做**：把 cue 改写成纯关键词（P3s 已证明没必要且会打坏 display 语义）、模型运行期改写查询（P0′ 已否证）、换 tokenizer、引分词依赖、嵌入/连续阈值、下调统计门槛。

## 8. 对用户原始设想的最终回应（据实测修订）

"**cue 只存关键词、命中后回整段叙述**"拆成两半看：

1. **"命中后回整段叙述"** —— 成立、低风险、不违反零正文，建议第 2 步做。
2. **"cue 只存关键词"** —— 实测证明**不需要**。保留叙述型 cue + 读出侧片段匹配就能 16/16；把 cue 压成纯关键词反而缩小了可撞词面，还会打坏 `display_cues` 的展示语义（评审三 N-4 已提示 cue 双角色问题）。


**第 0 步：零生产代码的离线对照实验（建议立即做，仍是 untracked 测试侧产物）**

用已验通的 SCNet-Max 把 16 条真人问法改写成 2–6 字短语，再喂现有**未改一行**的 `searchCardsExplained + applyGate` 纯函数离线跑：

- 臂 P0：整句直打（已知 0/16，基线）；
- 臂 P0′：模型改写短语 + 现门（验证 C1 到底能救回多少，含 2 字词失败率）；
- 记录 FTS 候选数/门放行数/返回数三段计数（同时补 R2 要求的漏斗可观测性原型）。

这一步直接回答"不改生产码现状能恢复多少召回"，并给甲/乙/丙三方案的必要性分级提供数据。

**第 1 步（低风险、与召回解耦）**：叙述回读窄面（eventId → 当前版本 summary，带 provenance 与截断上限），配 D1/D2/D3 定向诱饵。

**第 2 步（数据说话后三选一）**：按第 0 步结果在甲/乙/丙中立项，门若升版须红测先行、单调超集（旧放行的不回归）、shadow 行带版本号。

**明确不做**：门方向裸反转、换 tokenizer、卡上冗余叙述、别名自动写、嵌入/连续阈值、下调统计门槛。

## 7. 对用户原始设想的最终回应

"**cue 只存关键词、命中后回整段叙述**"方向被三方一致认可，但落点修正为：

1. "回整段叙述"（返回面）立即可以做、风险最低、不违反零正文；
2. "只存关键词"（写入/匹配面）**不能裸做**——2 字关键词在 trigram 下无候选、裸反向门会被泛词误召冲垮；必须配离散的稀有度/交叉确认，且先让第 0 步实验证明模型改写臂是否已经够用，避免过度工程。
