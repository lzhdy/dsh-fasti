# 待议备忘：成长可视化看板 / 桌宠 / 三端互通

> 状态：**仅记账，暂缓详谈**。用户判断软件主体未搭起来之前做展示层用不上，待后续专门讨论。
> 记录日期：2026-11-10。本文件只存结论与预留点，不含实施计划。

## 1. 诉求（会继续扩展，当前仅为初步想法）

- 一个"好看的网页"，实时观察她的成长：经历痕迹、记忆、情绪、动作等板块，板块未定死。
- 远期可能做成**桌宠**形态。
- 希望**三端互通**（多设备看到同一个她、同一份记忆）。

## 2. 初步可行性结论（2026-11-10 评估，未实施）

总判断：三者在现有地基上都属于**外挂消费层，不需要改不可变真源、不动记忆内核**，
无架构级阻断点。

- **只读看板**：数据已具备（experience/event/edge 投影 + 只读查询 API + jsonl 真源）；
  展示端不产生写入，与写入进程物理隔离，独立进程 + 只读连接 + 仅绑 127.0.0.1。
- **桌宠**：技术成熟，Tauri 2 / Electron 原生支持透明、置顶、无边框、点击穿透、不占任务栏；
  本质是换一个前端壳调用同一套接口。
- **三端互通**：走 local-first 路线（CRDT/LWW + 混合逻辑时钟）。本系统真源是 append-only
  只增日志、带全局 ULID 幂等键，属最易同步的数据形态（多端各写、按 id 去重合并即可）；
  投影是可重建派生品，不双向同步，各端从真源本地重建。

## 3. 必须提前预留、但现在不必改代码的点（防返工）

1. **时钟/tick 的去中心化**：当前 tick 靠单进程 max+1 分配，是单机假设。多端同时写入时需能
   平滑换成混合逻辑时钟（HLC）或直接以 ULID 定序。这是唯一识别到的内核级预留项，
   正式做多端前要先确认该升级路径。
2. **情绪字段尚不存在**：契约层目前没有任何 emotion/mood 字段。看板或桌宠要表现情绪，
   须先把情绪设计为经历/事件的一个可加维度（开放枚举加字段，向后兼容；不改正文真源）。
3. **媒体资产层（阶段 3+）**：`ingestMedia/preserveMedia/getMedia` 仍抛 NotImplementedError；
   看板/桌宠大概率要展示图片视频，设计媒体层时需一并考虑多端存储与引用形态。
4. 持续守住主线：真源 append-only 不可变，其余一切（看板、桌宠、记忆本、情绪、实体、同步）
   都做成可重建的外挂投影/消费者。
