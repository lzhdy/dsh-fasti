## 1. 第一命题：三不变

**命题**：FasTI 只有三样东西不可替换——记忆真源、自加工成长职能（复盘／做梦）、不注入与自成长；其余全部是零件。

判据不是"重不重要"，而是**去掉它，「她」会坍缩成什么**：

| 去掉 | 坍缩成 | 所以它是不变 |
|---|---|---|
| 真源 | 一个会话内的检索工具，关掉即忘 | 她的本体 |
| 复盘／做梦 | 一个冻结的索引库，永远长不大、不会改主意 | 她的动力学 |
| 不注入／自成长 | 角色扮演，人格由外部写好 | 她的来处 |

### 1.1 真源：不变的是本体，不是格式

- **是什么**：唯一 append-only 的原始事实层（`experiences/`＋`raw-turns/`＋`events/`），她经历过的每一件事只在这里，且只能追加。
- **不变到什么程度**：跨引擎、跨模型、跨宿主、跨设备恒等。任何零件不得绕开真源自建事实状态；投影（含 `memory-index`）一律可弃、可确定性重建。
- **不冻结什么**：文件格式的**具体字节**可变，但必须走版本化迁移＋确定性重放并可对账（见 3.3）。2026-11-15 的空白重启不许再演一次"因为改不动就得清空"。

### 1.2 复盘／做梦：不变的是职能，不是实现

- **不变的部分**：她必须能在没有外部指令的情况下，自己回顾、重排、连接、遗忘、得出结论——**且产出的东西进真源**（kind=reflection 通道，目前冻结未解冻），不可被某个零件直接改写。
- **可变的部分**：复盘引擎、做梦引擎、触发方式、批处理粒度、模型选择，全部可换。
- **推论**：C3 的闹钟是**她手里的工具**（她自己决定何时复盘、何时提醒自己），不是系统定时器。旧文档"凌晨 2 点定时复盘"的死因正在于此——系统替她决定何时反思。

### 1.3 不注入／自成长：不是第三个零件，是考官

它和另两条不在同一个层级上，写法要分清：

- 前两条是**被保护的对象**；
- 这一条是**对所有零件（含前两条的实现形态）的准入门槛**。

任何改动，只要使她的身份、人格、表达方式、判断结论由外部预设提供（角色卡、人设字段、系统代写的"我是谁"、代为得出的重要性判断、MUST 式指令），**直接淘汰，没有折中版本**。它的可执行形态就是红线考题：静态门、禁列测试、变异反证、后门扫描。

## 2. 第二命题：平台独立化（第一命题的直接推论）

**命题**：她不"住在"某个宿主里。宿主只是她可以接入的身体之一；同一个她可以接入任意平台，也可以裸连 LLM。

### 2.1 三条推论

1. **契约层不许出现宿主概念。** 契约是她的骨架，骨架不能长在别人的骨头上。
2. **一切外部能力必须经端口注入**：LLM、embedding、存储、时钟／心跳、事件源。端口是接口＋假实现＋契约测试，实现可换、可缺、可多。
3. **单写者纪律不变，但形态松绑**："同一数据根同时只允许一个写实例"继续成立（靠锁与队列保证）；"必须以 cordis 插件形态装载进宿主进程"不再成立。

## 3. 第三命题：可替换件与准入三考

### 3.1 可替换件清单（现行实现＋冻结接口）

| 零件 | 现行实现 | 可换 | 冻结的接口／形状 |
|---|---|---|---|
| 索引引擎 | FTS5 unicode61 v3（#124 刚换过） | 是 | 库文件契约、revision／shadowDiff 对账口径 |
| 检索打分 | 平坦 BM25＋IDF＋近因先验 | 是 | `ExplainedRankedCard` 形状与"必须可解释" |
| 窗口装配 | 五槽（#116，零调用） | 是（本来就要重议） | 对外只吐 cardId，不吐正文 |
| 建卡／派生 | builder／derive／planner | 是 | 禁列、停用词表、cue 派生白名单属考题 |
| 评分 | 现无（三维待建） | 是 | 分数不得反写真源 |
| 留存／遗忘 | #117 五件套 | 是 | 删除闭包不可违 |
| LLM | `src/event/llm-port.ts` | 是 | 端口形状；失败抛错不糊占位 |
| embedding | **无（缺口）** | — | 需新建端口 |
| 存储 | sqlite＋JSONL | 是 | 断点退化姿态（9.5） |
| 宿主适配 | `adapters/dsh/` | 是／可增 | 适配器薄壳，业务全在内核 |

### 3.2 冻结三样（换零件时不许动）

1. **真源格式契约**：字段级定义＋schema 版本号＋迁移可确定性重放；
2. **零件间接口契约**：只读窄柄、工具对外 DTO 白名单（只回 cardId／序号／锚点／线索／门原因）；
3. **红线考题**：静态门、禁列测试、变异反证、后门扫描、真源重建对账。

### 3.3 准入三考（换任何一个零件，三考全过才准上）

1. **契约一致**：不动真源格式、不动窄柄、不动 DTO 形状；需要动就走版本化迁移＋重放对账。
2. **红线测试全过**：现有全部红线考（`npm run verify` 唯一口径）＋新增零件的变异反证（至少 5 点，且能证伪）。
3. **真源确定性重建可对账**：拿真机真源重建投影，与现有库逐行对得上；对不上的差异必须逐条解释。

### 3.4 防折腾纪律（防止"出现更好的就推倒"）

- 触发替换必须**解决一个实测问题**（有数据、有复现、有未达标的判据），不接受"理论上更优"；
- **影子期零未解释回归**：shadow 跑一段，差异逐条归因；
- **冷备＋原子切换**：切换前冷备，切换后 revision 记账，真源零写入；
- 无实测问题时不换。这条比三考更重要——三考防坏零件，这条防好零件把项目拖死。

### 3.5 先例实证

#124 换索引引擎就是这套流程的第一次完整跑通：真源／投影分离 → 确定性重建 → 24 小时对账 → 冷备 → 原子切换 → 真机 revision 4、shadowDiff 全 0、真源零写入。**它证明"可替换"不是口号，是可重复的工程动作。**

**Q2 embedding → 已澄清并定稿。** embedding 不是摘要：摘要是「长文本→短文本」，走既有 `src/event/llm-port.ts`，且**已经是可选项**（端口为 null 时事件照常闭合、摘要保持 `pending`，代码见 `closure.ts:156`，不伪造）。embedding 是另一件事——「文本→向量」，用于语义相似召回，目前**完全没有端口**（属 #88／K1 的向量路线）。定为**独立可选端口**：优先级链 本地模型 > 平台提供 > 无（降级为纯词法）。平台提供只作可选实现，不得成为启动前提。

## 5A. 零件的定义（Q5 答案，待确认）

一句话判据：**换掉它，她还是她，只是变快／变准／变强 → 它是零件；换掉她就不认得自己了 → 它是骨架。**

操作化三条，满足任一即属"零件"，须受准入三考：

1. **它实现的是「怎么做」，不是「记什么」**：算法、引擎、索引结构、模型、存储格式、装配策略、调度方式；
2. **整体替换时真源字节不变、她对自我的认知不变**：只改变产出质量，不改变她的经历与判断；
3. **它有可度量的替换收益**：能指向一个实测指标（召回率、时延、体积、可解释性）。

据此划线：

| 属零件（可换，受三考） | 属骨架（不可换，只可版本化演进） |
|---|---|
| 索引引擎、检索打分、窗口装配、建卡／派生、评分算法、留存策略、LLM 实现、embedding 实现、存储实现、宿主适配器 | 真源格式契约、零件间窄柄与工具 DTO、红线考题、复盘／做梦**职能**、删除闭包 |

**关键区分（回答"评分算不算"）**：**判断归她，算法是零件。** 打分／留存都只是「实现她判断的工具」——算法可换，但① 不得反写真源，② 不得替她得出结论（只标记、不否决），③ 必须记录依据可追溯。满足这三条的打分器是合法零件；一旦它开始替她决定"这条不重要、直接不记"，它就越过红线变成骨架篡位者，必须淘汰。

## 5B. 遗忘的两阶段（待讨论，用户 2026-11-17 提出）

**命题**：遗忘不等于立即物理删除。先打标记，达到条件再真删。

### 阶段一：标记（mark-for-forget）

- 产出是**一行 append-only 决策**（不修改原记录）：卡片置 `status='invalid'|'superseded'`，真源原文一字不动；
- 被标记项**默认不召回**（可降权或直接进不召回集），但**可撤回**——她改主意就再写一行恢复决策；
- 标记权归她（红线 B：她的判断优先于系统规则）；规则只能**提名候选**，不能替她否决。

### 阶段二：物理清除（purge）

只有同时满足下列才执行，缺一条就继续挂着：

1. **冷却期已过**（可配置；她在冷却期内可撤回）；
2. **她未撤回**；
3. **备份已轮转**（否则备份里还能捞出，属于假删除）；
4. **跨设备同步已确认**（E 块到位前的隐私删除按 4.7 立 M9，不做假删除）；
5. **删除闭包全链打穿**：原文指针、结构条目、投影卡、索引轻卡、影子观测、备份保留策略全部有确定去向。

### 两条必须同时立起来的纪律

- **真删是唯一打破 append-only 的动作**，所以必须留 tombstone 并让 `DeletedError`（`src/core/errors.ts:63`，目前只是契约占位）真正抛出，"已删除／从未存在"两态可机器区分；
- **隐私／法律删除走即时通道**，不受冷却期约束、不等冷却——这是与"她自己遗忘"完全不同的一条路，必须分开设计，不能合成一套。

### 与 #117 的关系

#117 的留存上限本质是"遗忘的容量侧"，两阶段遗忘是"遗忘的语义侧"。二者必须**合并设计**，否则会出现两套互相打架的遗忘逻辑：上限到了该不该真删？建议口径——**上限只触发标记提名，不触发物理删除**；物理删除永远走阶段二五条件。

## 5C. 与本次讨论无关但已发现的缺口（不在本提案范围，另立卡）

1. **删除能力零实现**（本文 5B 的前提）；
2. **跨进程写者互斥缺失**（现在只有进程内 `WriterQueue`，无跨进程锁）；
3. **无宿主启动路径**（入口只有 `adapters/dsh/plugin.ts`）；
4. **clock／tick 端口缺失**（`checkSilenceClock(nowMs = Date.now())` 由 plugin 驱动）；
5. **无"身体"维度**（channel 无法区分多平台来源）；
6. **无端到端闭环判据**；
7. **评分依赖复盘解冻**。
